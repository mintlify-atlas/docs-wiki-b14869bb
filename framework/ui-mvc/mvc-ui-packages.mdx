`Volo.Abp.AspNetCore.Mvc.UI.Packages` is **the catalogue of vendor packs** ABP officially supports for MVC UIs. For every NPM package it ships, the assembly contains one — sometimes two — `BundleContributor`s:

- a *script* contributor that adds the JS files (e.g. `BootstrapScriptContributor` → `/libs/bootstrap/js/bootstrap.bundle.js`);
- a *style* contributor (where relevant) that adds the CSS (e.g. `BootstrapStyleContributor` → `/libs/bootstrap/css/bootstrap.css` or its RTL twin);
- a small *options* class when the contributor exposes user-configurable paths (e.g. `JsTreeOptions.StylePath`).

These contributors are how a downstream module — your code, a theme, a CMS-kit module — declares a dependency on a vendor lib **without hard-coding the file path**. You just `AddContributors(typeof(JQueryScriptContributor))` and the framework handles ordering, deduplication, RTL swap, and locale-aware sub-files.

## Module

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Packages/Volo/Abp/AspNetCore/Mvc/UI/Packages/AbpAspNetCoreMvcUiPackagesModule.cs
[DependsOn(
    typeof(AbpAspNetCoreMvcUiBundlingAbstractionsModule),
    typeof(AbpLocalizationModule)
)]
public class AbpAspNetCoreMvcUiPackagesModule : AbpModule
{
    public override void ConfigureServices(ServiceConfigurationContext context)
    {
        Configure<AbpLocalizationOptions>(options =>
        {
            //BootstrapDatepicker
            options.AddLanguagesMapOrUpdate(BootstrapDatepickerScriptContributor.PackageName,
                new NameValue("zh-Hans", "zh-CN"),
                new NameValue("zh-Hant", "zh-TW"));

            options.AddLanguageFilesMapOrUpdate(BootstrapDatepickerScriptContributor.PackageName,
                new NameValue("zh-Hans", "zh-CN"),
                new NameValue("zh-Hant", "zh-TW"));

            //moment
            options.AddLanguagesMapOrUpdate(MomentScriptContributor.PackageName,
                new NameValue("zh-Hans", "zh-cn"),
                new NameValue("zh-Hant", "zh-tw"));

            options.AddLanguageFilesMapOrUpdate(MomentScriptContributor.PackageName,
                new NameValue("zh-Hans", "zh-cn"),
                new NameValue("zh-Hant", "zh-tw"));

            //Timeago
            options.AddLanguageFilesMapOrUpdate(TimeagoScriptContributor.PackageName,
                new NameValue("zh-Hans", "zh-CN"),
                new NameValue("zh-Hant", "zh-TW"));

            //JQueryValidation
            options.AddLanguageFilesMapOrUpdate(JQueryValidationScriptContributor.PackageName,
                new NameValue("zh-Hans", "zh"),
                new NameValue("zh-Hant", "zh_TW"));
        });
    }
}
```

The module body is mostly **culture-name mapping**: ABP uses the `zh-Hans` / `zh-Hant` `CultureInfo` names, while vendor libraries use the older `zh-CN` / `zh-TW` (or moment's `zh-cn` / `zh-tw`). The map ensures that when a Simplified-Chinese user views the page, `MomentScriptContributor` loads `/libs/moment/locale/zh-cn.js` rather than failing to find `zh-Hans.js`.

## The `Core` baseline

The framework ships its own tiny script/style entry point (`abp.js` + `abp.css`) — `CoreScriptContributor` and `CoreStyleContributor` are the contributors used by every other pack as a transitive dependency.

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Packages/Volo/Abp/AspNetCore/Mvc/UI/Packages/Core/CoreScriptContributor.cs
[DependsOn(typeof(UtilsScriptContributor))]
public class CoreScriptContributor : BundleContributor
{
    public override void ConfigureBundle(BundleConfigurationContext context)
    {
        context.Files.AddIfNotContains("/libs/abp/core/abp.js");
    }
}
```

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Packages/Volo/Abp/AspNetCore/Mvc/UI/Packages/Core/CoreStyleContributor.cs
public class CoreStyleContributor : BundleContributor
{
    public override void ConfigureBundle(BundleConfigurationContext context)

```

## jQuery, Bootstrap and FontAwesome

These three appear everywhere because of the dependency chains the higher-level packs declare.

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Packages/Volo/Abp/AspNetCore/Mvc/UI/Packages/JQuery/JQueryScriptContributor.cs
[DependsOn(typeof(CoreScriptContributor))]
public class JQueryScriptContributor : BundleContributor
{
    public override void ConfigureBundle(BundleConfigurationContext context)
    {
        context.Files.AddIfNotContains("/libs/jquery/jquery.js");
        context.Files.AddIfNotContains("/libs/abp/jquery/abp.jquery.js");
    }
}
```

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Packages/Volo/Abp/AspNetCore/Mvc/UI/Packages/Bootstrap/BootstrapScriptContributor.cs
[DependsOn(typeof(JQueryScriptContributor))]
public class BootstrapScriptContributor : BundleContributor
{
    public override void ConfigureBundle(BundleConfigurationContext context)
    {
        context.Files.AddIfNotContains("/libs/bootstrap/js/bootstrap.bundle.js");
    }
}
```

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Packages/Volo/Abp/AspNetCore/Mvc/UI/Packages/Bootstrap/BootstrapStyleContributor.cs
public class BootstrapStyleContributor : BundleContributor
{
    public override void ConfigureBundle(BundleConfigurationContext context)
    {
        if (CultureHelper.IsRtl)
            context.Files.AddIfNotContains("/libs/bootstrap/css/bootstrap.rtl.css");
        else
            context.Files.AddIfNotContains("/libs/bootstrap/css/bootstrap.css");
    }
}
```

`BootstrapStyleContributor` is the canonical example of the **RTL swap**: at request time the same contributor adds a different file depending on the current culture's text direction.

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Packages/Volo/Abp/AspNetCore/Mvc/UI/Packages/FontAwesome/FontAwesomeStyleContributor.cs
public class FontAwesomeStyleContributor : BundleContributor
{
    public override void ConfigureBundle(BundleConfigurationContext context)
    {
        context.Files.AddIfNotContains("/libs/@fortawesome/fontawesome-free/css/all.css");
        context.Files.AddIfNotContains("/libs/@fortawesome/fontawesome-free/css/v4-shims.css");
    }
}
```

`v4-shims.css` is added so themes that still emit FA4 class names (`fa fa-pencil`) keep working alongside FA5/6's renamed icons.

## Locale-aware: Moment and friends

`MomentScriptContributor` uses the `ConfigureDynamicResources` phase to add the per-culture locale file as a *dynamic* resource — meaning it is **always emitted as its own `<script>` tag**, never minified into the bundle (because the file depends on the current request culture).

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Packages/Volo/Abp/AspNetCore/Mvc/UI/Packages/Moment/MomentScriptContributor.cs
public class MomentScriptContributor : BundleContributor
{
    public const string PackageName = "moment";

    public override void ConfigureBundle(BundleConfigurationContext context)
    {
        context.Files.AddIfNotContains("/libs/moment/moment.min.js");
    }

    public override void ConfigureDynamicResources(BundleConfigurationContext context)
    {
        var fileName = context.LazyServiceProvider
            .LazyGetRequiredService<IOptions<AbpLocalizationOptions>>()
            .Value
            .GetCurrentUICultureLanguageFilesMap(PackageName);

        var filePath = $"/libs/moment/locale/{fileName}.js";
        if (context.FileProvider.GetFileInfo(filePath).Exists)
            context.Files.AddIfNotContains(filePath);
    }
}
```

`GetCurrentUICultureLanguageFilesMap` looks up the moment-specific culture name through the maps the package module registers (so `zh-Hans` → `zh-cn` and the right file gets loaded).

The same pattern is used by `BootstrapDatepickerScriptContributor`, `TimeagoScriptContributor`, `JQueryValidationScriptContributor`, etc.

## Options-driven: JsTree

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Packages/Volo/Abp/AspNetCore/Mvc/UI/Packages/JsTree/JsTreeOptions.cs
public class JsTreeOptions
{
    /// <summary>
    /// Path of the style file for the JsTree library.
    /// Setting to null ignores the style file.
    /// Default value: "/libs/jstree/themes/default/style.min.css".
    /// </summary>
    public string StylePath { get; set; } = "/libs/jstree/themes/default/style.min.css";
}
```

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Packages/Volo/Abp/AspNetCore/Mvc/UI/Packages/JsTree/JsTreeScriptContributor.cs
[DependsOn(typeof(JQueryScriptContributor))]
public class JsTreeScriptContributor : BundleContributor
{
    public override void ConfigureBundle(BundleConfigurationContext context)
    {
        context.Files.AddIfNotContains("/libs/jstree/jstree.min.js");
    }
}
```

The options class is independently registered via the conventional auto-register; the corresponding style contributor reads it through `context.LazyServiceProvider`. This pattern lets a theme that ships a custom JsTree skin change the default style file with two lines.

## Why the wrappers matter

Without the wrapper layer, every theme would need to know the precise file paths of every vendor pack — and the framework would not be able to:

- swap RTL stylesheets transparently;
- defer the locale-specific moment file outside the bundle;
- topologically sort contributors using `[DependsOn]`;
- consolidate duplicate adds across modules (because everyone calls `AddIfNotContains`).

A real-world example: when LeptonX adds a custom Datatables theme, it simply does:

```csharp
options.StyleBundles
    .Get(StandardBundles.Styles.Global)
    .AddContributors(typeof(DatatablesNetBs5StyleContributor))
    .AddFiles("/themes/leptonx/datatables-overrides.css");
```

…and is guaranteed the underlying `dataTables.bootstrap5.css` loaded first.
