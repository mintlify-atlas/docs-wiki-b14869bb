`Volo.Abp.AspNetCore.Mvc.UI.Theme.Shared` is the **base theme** that every concrete MVC theme (the Basic theme, LeptonX, custom themes) inherits from. It does not ship a `_Layout.cshtml` of its own; instead it defines the **services and bundles that every layout consumes**:

- `IToolbarManager` + `AbpToolbarOptions` + `IToolbarContributor` — the contribution model for header toolbars (left, right, user menu).
- `IPageToolbarManager` + `AbpPageToolbarOptions` — page-scoped toolbars (per Razor page, e.g. "Refresh / Export / Filter").
- `SharedThemeGlobalScriptContributor` + `SharedThemeGlobalStyleContributor` — the two contributors that aggregate every common vendor pack into the `Global` bundles.
- `ErrorController` + `AbpErrorPageOptions` — the conventional 4xx/5xx fallback page.
- A set of shared view components (`AbpApplicationPath`, `AbpPageSearchBox`, `AbpPageToolbar`, `AbpPageToolbarButton`) reused by every theme.

## Module

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Theme.Shared/AbpAspNetCoreMvcUiThemeSharedModule.cs
[DependsOn(
    typeof(AbpAspNetCoreMvcUiBootstrapModule),
    typeof(AbpAspNetCoreMvcUiPackagesModule),
    typeof(AbpAspNetCoreMvcUiWidgetsModule)
)]
public class AbpAspNetCoreMvcUiThemeSharedModule : AbpModule
{
    public override void PreConfigureServices(ServiceConfigurationContext context)
    {
        PreConfigure<IMvcBuilder>(mvcBuilder =>
        {
            mvcBuilder.AddApplicationPartIfNotExists(typeof(AbpAspNetCoreMvcUiThemeSharedModule).Assembly);
        });
    }

    public override void ConfigureServices(ServiceConfigurationContext context)
    {
        Configure<AbpVirtualFileSystemOptions>(options =>
        {
            options.FileSets.AddEmbedded<AbpAspNetCoreMvcUiThemeSharedModule>(
                "Volo.Abp.AspNetCore.Mvc.UI.Theme.Shared");
        });

        Configure<AbpBundlingOptions>(options =>
        {
            options.StyleBundles.Add(
                StandardBundles.Styles.Global,
                bundle => bundle.AddContributors(typeof(SharedThemeGlobalStyleContributor)));

            options.ScriptBundles.Add(
                StandardBundles.Scripts.Global,
                bundle => bundle.AddContributors(typeof(SharedThemeGlobalScriptContributor)));
        });
    }
}
```

So **the act of depending on this module is what creates the `Global` style and script bundles** in every ABP MVC application.


The `[DependsOn]` list pulls every vendor pack ABP MVC pages take for granted (`abp.modal`, `abp.notify`, the datatables wrapper, the modal manager…). Each of those packs in turn `[DependsOn]` their own deps, so by the time `BundleManager` finishes topologically sorting, you have `core → utils → jquery → bootstrap → lodash → validation → select2 → datatables-bs5 → sweetalert2 → toastr → …`.

After the deps, the contributor adds the **ABP-specific glue scripts** — `widget-manager.js`, `modal-manager.js`, `abp-sweetalert2.js` (the `abp.message.*` API), `abp-toastr.js` (the `abp.notify.*` API), and so on.

### Execution

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Theme.Shared/Toolbars/ToolbarManager.cs
public class ToolbarManager : IToolbarManager, ITransientDependency
{
    public async Task<Toolbar> GetAsync(string name)
    {
        var toolbar = new Toolbar(name);

        using (var scope = ServiceProvider.CreateScope())
        using (RequirePermissionsSimpleBatchStateChecker<ToolbarItem>.Use(
                  new RequirePermissionsSimpleBatchStateChecker<ToolbarItem>()))
        {
            var context = new ToolbarConfigurationContext(
                ThemeManager.CurrentTheme, toolbar, scope.ServiceProvider);

            foreach (var contributor in Options.Contributors)
                await contributor.ConfigureToolbarAsync(context);

            await CheckPermissionsAsync(scope.ServiceProvider, toolbar);
        }
        return toolbar;
    }
}
```

The flow mirrors `MenuManager`: instantiate, run all contributors inside a scope, batch-check `RequirePermissions(...)`, drop denied items. Themes call `_toolbarManager.GetAsync(StandardToolbars.Main)` from a `_Toolbar.cshtml` partial.

## Page toolbars

A *page* toolbar is the secondary toolbar attached to a specific Razor page (e.g. the user-list page's "New user" + "Export" buttons). The contracts mirror the header toolbar but are keyed by page name (the page's full type name):

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Theme.Shared/PageToolbars/AbpPageToolbarOptions.cs
public class AbpPageToolbarOptions
{
    public PageToolbarDictionary Toolbars { get; }

    public void Configure<TPage>(Action<PageToolbar> configureAction)
        => Configure(typeof(TPage).FullName!, configureAction);

    public void Configure(string pageName, Action<PageToolbar> configureAction)
    {
        var toolbar = Toolbars.GetOrAdd(pageName, () => new PageToolbar(pageName));
        configureAction(toolbar);
    }
}
```

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Theme.Shared/PageToolbars/PageToolbarItem.cs
public class PageToolbarItem
{
    public Type ComponentType { get; }
    public object? Arguments { get; set; }
    public int Order { get; set; }
}
```

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Theme.Shared/PageToolbars/PageToolbarManager.cs
public class PageToolbarManager : IPageToolbarManager, ITransientDependency
{
    public virtual async Task<PageToolbarItem[]> GetItemsAsync(string pageName)
    {
        var toolbar = Options.Toolbars.GetOrDefault(pageName);
        if (toolbar == null || !toolbar.Contributors.Any())
            return Array.Empty<PageToolbarItem>();

        using (var scope = ServiceScopeFactory.CreateScope())
        {
            var context = new PageToolbarContributionContext(pageName, scope.ServiceProvider);
            foreach (var contributor in toolbar.Contributors)
                await contributor.ContributeAsync(context);

            return context.Items.OrderBy(i => i.Order).ToArray();
        }
    }
}
```

The convenient `SimplePageToolbarContributor` covers the common "add this component with an optional policy" case:

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Theme.Shared/PageToolbars/SimplePageToolbarContributor.cs
public class SimplePageToolbarContributor : IPageToolbarContributor
{
    public Type ComponentType { get; }
    public object? Argument { get; set; }
    public int Order { get; }
    public string? RequiredPolicyName { get; }

    public async Task ContributeAsync(PageToolbarContributionContext context)
    {
        if (await ShouldAddComponentAsync(context))
            context.Items.Add(new PageToolbarItem(ComponentType, Argument, Order));
    }

    protected virtual async Task<bool> ShouldAddComponentAsync(PageToolbarContributionContext context)
    {
        if (RequiredPolicyName != null)
        {
            var authorizationService = context.ServiceProvider
                .GetRequiredService<IAuthorizationService>();
            if (!await authorizationService.IsGrantedAsync(RequiredPolicyName))
                return false;
        }
        return true;
    }
}
```

## Error page

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Theme.Shared/AbpApplicationBuilderErrorPageExtensions.cs
public static IApplicationBuilder UseErrorPage(this IApplicationBuilder app)
{
    return app
        .UseStatusCodePagesWithRedirects("~/Error?httpStatusCode={0}")
        .UseExceptionHandler("/Error");
}
```

That's the single line that production ASP.NET Core hosts add to redirect every 4xx/5xx to ABP's branded error page. The page is served by `ErrorController`:

```csharp framework/src/Volo.Abp.AspNetCore.Mvc.UI.Theme.Shared/Controllers/ErrorController.cs
public class ErrorController : AbpController
{
    public virtual async Task<IActionResult> Index(int httpStatusCode)
    {
        var exHandlerFeature = HttpContext.Features.Get<IExceptionHandlerFeature>();
        var exception = exHandlerFeature?.Error
                        ?? new Exception(Localizer["UnhandledException"]);

        await ExceptionNotifier.NotifyAsync(new ExceptionNotificationContext(exception));

        var errorInfo = ErrorInfoConverter.Convert(exception, options =>
        {
            options.SendExceptionsDetailsToClients = ExceptionHandlingOptions.SendExceptionsDetailsToClients;
            options.SendStackTraceToClients = ExceptionHandlingOptions.SendStackTraceToClients;
        });

        if (httpStatusCode == 0)
            httpStatusCode = (int)StatusCodeFinder.GetStatusCode(HttpContext, exception);

        HttpContext.Response.StatusCode = httpStatusCode;

        var page = GetErrorPageUrl(httpStatusCode);
        return View(page, new AbpErrorViewModel { ErrorInfo = errorInfo, HttpStatusCode = httpStatusCode });
    }
}
```

`AbpErrorPageOptions.ErrorViewUrls["404"]` lets you replace just the 404 page without overriding the rest, while every page still benefits from `IExceptionToErrorInfoConverter` + `IHttpExceptionStatusCodeFinder` (so a `EntityNotFoundException` automatically becomes a 404 even on the error page).
