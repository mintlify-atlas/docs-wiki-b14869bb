`Volo.Abp.AspNetCore.Mvc.UI.Theme.Basic` is the MVC / Razor Pages implementation of the [Basic Theme](/modules/basic-theme/overview). This page is the file-by-file reference: every Razor view, every view component, every contributor. For higher-level concepts (when to use Basic, what its visual contract is) start with the overview.

## Module wiring

```csharp
[DependsOn(
    typeof(AbpAspNetCoreMvcUiThemeSharedModule),
    typeof(AbpAspNetCoreMvcUiMultiTenancyModule)
)]
public class AbpAspNetCoreMvcUiBasicThemeModule : AbpModule
{
    public override void PreConfigureServices(ServiceConfigurationContext context)
    {
        PreConfigure<IMvcBuilder>(mvcBuilder =>
        {
            mvcBuilder.AddApplicationPartIfNotExists(typeof(AbpAspNetCoreMvcUiBasicThemeModule).Assembly);
        });
    }

    public override void ConfigureServices(ServiceConfigurationContext context)
    {
        Configure<AbpThemingOptions>(options =>
        {
            options.Themes.Add<BasicTheme>();
            if (options.DefaultThemeName == null)
                options.DefaultThemeName = BasicTheme.Name;
        });

        Configure<AbpVirtualFileSystemOptions>(options =>
        {
            options.FileSets.AddEmbedded<AbpAspNetCoreMvcUiBasicThemeModule>(
                "Volo.Abp.AspNetCore.Mvc.UI.Theme.Basic");
        });

        Configure<AbpToolbarOptions>(options =>
        {
            options.Contributors.Add(new BasicThemeMainTopToolbarContributor());
        });

        Configure<AbpBundlingOptions>(options =>
        {
            options.StyleBundles.Add(BasicThemeBundles.Styles.Global, b =>
                b.AddBaseBundles(StandardBundles.Styles.Global)
                 .AddContributors(typeof(BasicThemeGlobalStyleContributor)));

            options.ScriptBundles.Add(BasicThemeBundles.Scripts.Global, b =>
                b.AddBaseBundles(StandardBundles.Scripts.Global)
                 .AddContributors(typeof(BasicThemeGlobalScriptContributor)));
        });
    }
}
```

Four things happen in order:

1. The `MvcBuilder` is taught to discover the assembly's controllers and view components via `AddApplicationPartIfNotExists` — this is what lets the host project pick up the theme's view components without explicit registration.
2. `BasicTheme` is added to the theme registry and made the default if nobody has already claimed the slot.
3. The whole assembly is exposed as an embedded `FileSet` so layouts under `~/Themes/Basic/` resolve through `IVirtualFileProvider`.
4. The toolbar and bundle definitions are registered.

The bundle registration is the most important conceptual step: the Basic theme **extends** the framework's standard global bundles instead of replacing them. `AddBaseBundles(StandardBundles.Styles.Global)` pulls in Bootstrap, FontAwesome, the framework's `abp.js`, and every other contributor registered against the standard bundle; then `BasicThemeGlobalStyleContributor` appends `/themes/basic/layout.css`. This is the recommended way to add per-theme assets and the pattern you should follow for custom themes.

## The bundle contributors

```csharp
public class BasicThemeGlobalStyleContributor : BundleContributor
{
    public override void ConfigureBundle(BundleConfigurationContext context)
        => context.Files.Add("/themes/basic/layout.css");
}

public class BasicThemeGlobalScriptContributor : BundleContributor
{
    public override void ConfigureBundle(BundleConfigurationContext context)
        => context.Files.Add("/themes/basic/layout.js");
}
```

These two files live under `wwwroot/themes/basic/` and are tiny. `layout.css` overrides the navbar margin and tweaks the default Bootstrap container spacing; `layout.js` is a near-empty stub that exists so future per-theme JS can be added without touching the contributor signature.

`BasicThemeBundles` is the constants holder:

```csharp
public static class BasicThemeBundles
{
    public static class Styles  { public const string Global = "Basic.Global"; }
    public static class Scripts { public const string Global = "Basic.Global"; }
}
```

Inside layouts, the bundles are emitted with `<abp-style-bundle name="@BasicThemeBundles.Styles.Global" />` and `<abp-script-bundle name="@BasicThemeBundles.Scripts.Global" />`. The bundle name is the cache key; if you swap themes at runtime (rare) you must clear `IBundleManager`'s cache.

## The three layouts

### `Application.cshtml`

This is the layout returned by `GetLayout(StandardLayouts.Application)` and is used by every regular content page. Top to bottom:

```cshtml
<!DOCTYPE html>
<html lang="@CultureInfo.CurrentCulture.Name" dir="@rtl">
<head>
    @await Component.InvokeLayoutHookAsync(LayoutHooks.Head.First, StandardLayouts.Application)
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1, shrink-to-fit=no">
    <title>@pageTitle</title>
    <abp-style-bundle name="@BasicThemeBundles.Styles.Global" />
    @await Component.InvokeAsync(typeof(WidgetStylesViewComponent))
    @await RenderSectionAsync("styles", false)
    @await Component.InvokeLayoutHookAsync(LayoutHooks.Head.Last, StandardLayouts.Application)
</head>
<body class="abp-application-layout @rtl">
    @await Component.InvokeLayoutHookAsync(LayoutHooks.Body.First, StandardLayouts.Application)
    @(await Component.InvokeAsync<MainNavbarViewComponent>())
    <div class="@containerClass">
        @(await Component.InvokeAsync<PageAlertsViewComponent>())
        <div id="AbpContentToolbar">
            <div class="row mb-2">
                @(await Component.InvokeAsync<ContentTitleViewComponent>())
                <div class="col">
                    <div class="text-end">
                        @await RenderSectionAsync("content_toolbar", false)
                    </div>
                </div>
            </div>
        </div>
        @await Component.InvokeLayoutHookAsync(LayoutHooks.PageContent.First, StandardLayouts.Application)
        @RenderBody()
        @await Component.InvokeLayoutHookAsync(LayoutHooks.PageContent.Last, StandardLayouts.Application)
    </div>
    <abp-script-bundle name="@BasicThemeBundles.Scripts.Global" />
    <script src="~/Abp/ApplicationLocalizationScript?cultureName=@CultureInfo.CurrentUICulture.Name"></script>
    <script src="~/Abp/ApplicationConfigurationScript"></script>
    <script src="~/Abp/ServiceProxyScript"></script>
    @await Component.InvokeAsync(typeof(WidgetScriptsViewComponent))
    @await RenderSectionAsync("scripts", false)
    @await Component.InvokeLayoutHookAsync(LayoutHooks.Body.Last, StandardLayouts.Application)
</body>
</html>
```

Visually that produces: a dark navbar with brand on the left, centered menu, right-aligned toolbar; below it a Bootstrap container with an alerts strip, then an `AbpContentToolbar` row that puts the page title (`<h4>` from `ContentTitleViewComponent`) on the left and the page's `content_toolbar` section on the right; then the body; then the three framework scripts (localization, configuration, service proxy).

The title resolution algorithm is:

```csharp
var pageTitle = ViewBag.Title ?? BrandingProvider.AppName;
if (PageLayout.Content.Title != null)
{
    if (!string.IsNullOrWhiteSpace(pageTitle))
        pageTitle = " | " + pageTitle;
    pageTitle = PageLayout.Content.Title + pageTitle;
}
```

i.e., the page's own `IPageLayout.Content.Title` becomes a prefix and the app name a suffix, separated by `" | "`. Setting `ViewBag.Title` directly bypasses the prefix concatenation.

`containerClass` is `container` by default and `container-fluid` when `ViewBag.FluidLayout == true`. There is a `TODO` in source noting that this should become a type-safe option; for now you toggle full-width by writing `ViewBag.FluidLayout = true` in a page directive.

### `Account.cshtml`

The account layout is used by the Account module (login, register, forgot password, etc.). It differs from `Application.cshtml` in three ways:

- No `ContentTitleViewComponent` row — account pages render their own card.
- Body wraps the page content in `<abp-row><abp-column class="col mx-auto" style="max-width: 440px">`, giving the classic narrow form column.
- A conditional **tenant-switch panel** is rendered at the top of the column when multi-tenancy is enabled *and* the current tenant was resolved via cookie or query-string contributor:

```cshtml
@if (MultiTenancyOptions.Value.IsEnabled &&
     (TenantResolveResultAccessor.Result?.AppliedResolvers?.Contains(CookieTenantResolveContributor.ContributorName) == true ||
      TenantResolveResultAccessor.Result?.AppliedResolvers?.Contains(QueryStringTenantResolveContributor.ContributorName) == true))
{
    <div class="card shadow-sm rounded mb-3">
        ... current tenant name + "Switch" button ...
    </div>
}
```

This is the panel the Account module's `TenantSwitchModal` JavaScript opens. If the tenant was resolved via host header (`DomainTenantResolveContributor`) the panel hides — a host-mapped tenant cannot be switched without changing the URL.

### `Empty.cshtml`

The empty layout drops the navbar, the content title, the AbpContentToolbar row, and the user menu — everything except the alerts strip and `RenderBody`. It is used for error pages (`/Error`), embed pages, and standalone landing pages. Body class: `abp-empty-layout`.

## View components

### `MainNavbarViewComponent`

Trivial — returns the `Default.cshtml` view that composes Brand + Menu + Toolbar:

```cshtml
<nav class="navbar navbar-expand-md navbar-dark bg-dark shadow-sm flex-column flex-md-row mb-4"
     id="main-navbar" style="min-height: 4rem;">
    <div class="container">
        @(await Component.InvokeAsync<MainNavbarBrandViewComponent>())
        <button class="navbar-toggler" type="button" data-bs-toggle="collapse"
                data-bs-target="#main-navbar-collapse" ...>
            <span class="navbar-toggler-icon"></span>
        </button>
        <div class="collapse navbar-collapse" id="main-navbar-collapse">
            <ul class="navbar-nav mx-auto">
                @(await Component.InvokeAsync<MainNavbarMenuViewComponent>())
            </ul>
            <ul class="navbar-nav">
                @(await Component.InvokeAsync<MainNavbarToolbarViewComponent>())
            </ul>
        </div>
    </div>
</nav>
```

Bootstrap 5 attributes (`data-bs-*`) are used throughout — replacing the navbar wholesale in a custom theme is essentially copying this snippet and changing the colour class (`bg-dark` → e.g. `bg-primary`).

### `MainNavbarBrandViewComponent`

```cshtml
@inject IBrandingProvider BrandingProvider
<a class="navbar-brand" href="~/">
    @if (!BrandingProvider.LogoUrl.IsNullOrWhiteSpace())
    {
        <img src="@BrandingProvider.LogoUrl" alt="@BrandingProvider.AppName">
    }
    @BrandingProvider.AppName
</a>
```

Both the logo URL and app name come from `IBrandingProvider`. The framework default is `DefaultBrandingProvider` with `AppName = "MyProjectName"`; replacing this with a custom `IBrandingProvider` (registered with `[ExposeServices(typeof(IBrandingProvider))]`) is the standard way to customise app-name and logo without touching the theme. See [Theme Shared](/framework/ui-mvc/mvc-ui-theme-shared#branding-provider).

### `MainNavbarMenuViewComponent`

Pulls the main menu via `IMenuManager.GetMainMenuAsync()` and renders it through `Default.cshtml`, which delegates to `_MenuItem.cshtml` recursively for nested items. The renderer respects:

- `ApplicationMenuItem.Icon` (FontAwesome class).
- `RequiredPermissionName` (resolved by `MenuManager` before the contributor returns).
- `Order` (sorted ascending; default 1000).
- `Url` — emitted as `href`, supports `~/` paths.

### `MainNavbarToolbarViewComponent`

Iterates the contributed `Toolbar` items in order and invokes each as a view component. The Basic toolbar contributor adds at most two items (language + user menu); enterprise modules (Identity, AuditLogging, etc.) may add their own contributors that target the same `StandardToolbars.Main`.

### `ContentTitleViewComponent`

Reads `IPageLayout.Content` and renders `<h4>@Model.Title</h4>`. Note the markup is a single `<h4>` in a Bootstrap `<div class="col">` — there is no breadcrumb in the Application layout. Pages can populate breadcrumbs via `PageLayout.Content.BreadCrumb.Add(...)` and a custom layout can render them, but the default Basic layout intentionally omits the breadcrumb strip in favour of a clean look.

### `PageAlertsViewComponent`

```csharp
public IViewComponentResult Invoke(string name)
{
    return View("~/Themes/Basic/Components/PageAlerts/Default.cshtml", AlertManager.Alerts);
}
```

`IAlertManager.Alerts` is the per-request alert buffer; `IAlertManager.Success(...)`, `Warning(...)`, etc. enqueue items that this component renders as Bootstrap dismissable alerts at the top of the content area.

### `LanguageSwitchViewComponent`

Pulls `LanguageProvider.GetLanguagesAsync()`, resolves the current language by culture name, and falls back through `IAbpRequestLocalizationOptionsProvider.DefaultRequestCulture` when the resolver cannot match. The fallback exists to handle missing CultureInfo definitions on minimal Linux images — in normal hosts the first lookup succeeds. Renders a dropdown of "other" languages.

### `UserMenuViewComponent`

Pulls the `StandardMenus.User` menu via `IMenuManager.GetAsync("User")`. This menu is contributed by the Identity, Account, and other modules with items like "My account", "Settings", "Sign out". Renders as a Bootstrap dropdown anchored to the user's display name.

## Toolbar contributor

The contributor was shown in full in the [overview](/modules/basic-theme/overview#standard-toolbar-contributions). The two important nuances:

- The check `if (!(context.Theme is BasicTheme)) return;` means this contributor is **passive** when another theme is active — it does not pollute LeptonX's toolbar with duplicate items.
- The `languages.Count > 1` short-circuit hides the language dropdown when only English is configured. Add the language module (`Volo.Abp.LanguageManagement`) and the dropdown appears automatically.

## Layout hooks

Every layout invokes `Component.InvokeLayoutHookAsync(hookName, layoutName)` at the canonical positions:

- `LayoutHooks.Head.First` / `LayoutHooks.Head.Last`
- `LayoutHooks.Body.First` / `LayoutHooks.Body.Last`
- `LayoutHooks.PageContent.First` / `LayoutHooks.PageContent.Last`

These hooks accept registrations through `AbpLayoutHookOptions` and are the canonical extension point for injecting third-party widgets without overriding the layout itself. See [Theme Shared — Layout hooks](/framework/ui-mvc/mvc-ui-theme-shared#layout-hooks) for the full list and an example registration.

## Customisation recipes

### Switch the navbar colour

The Bootstrap utility classes `navbar-dark bg-dark` drive the navbar palette. Override them with a CSS rule in your host bundle:

```css
#main-navbar {
    background-color: #1e3a8a !important;  /* indigo-800 */
}
```

The selector is `#main-navbar` which is on the `<nav>` itself. Avoid editing the embedded `MainNavbar/Default.cshtml` — `wwwroot/themes/basic/layout.css` is the friendlier surface, but adding a host-level CSS file via a custom `BundleContributor` is cleaner still.

### Replace the brand

```csharp
[ExposeServices(typeof(IBrandingProvider))]
public class MyBrandingProvider : DefaultBrandingProvider
{
    public override string AppName => "Acme Cloud";
    public override string LogoUrl => "/images/acme-logo.png";
    public override string LogoReverseUrl => "/images/acme-logo-light.png";
}
```

`LogoUrl` is used in the dark navbar; `LogoReverseUrl` is reserved for layouts that need a light-on-dark variant (none of the Basic layouts use it directly, but LeptonX and custom themes might).

### Override a single layout file

Drop a `Themes/Basic/Layouts/Application.cshtml` into your host project under the same virtual path. The virtual file system's *last contributor wins* rule means your file overrides the embedded one without any code change. See [Customizing Application Modules: MVC](/framework/ui-mvc/customizing-mvc-views).

### Add an item to the right toolbar

Write an `IToolbarContributor`:

```csharp
public class MyToolbarContributor : IToolbarContributor
{
    public Task ConfigureToolbarAsync(IToolbarConfigurationContext context)
    {
        if (context.Toolbar.Name == StandardToolbars.Main)
        {
            context.Toolbar.Items.Add(new ToolbarItem(typeof(MyAlertsViewComponent), order: 100));
        }
        return Task.CompletedTask;
    }
}
```

Register with `Configure<AbpToolbarOptions>(o => o.Contributors.Add(new MyToolbarContributor()));`. Order determines left-to-right placement among toolbar items.

## Gotchas

- **`MainNavbar/Default.cshtml` has a stray control-character artefact** (visible in the raw source) between the menu `</ul>` and the toolbar `<ul>`. It is non-rendering whitespace and the file compiles cleanly via Razor, but custom edits should preserve UTF-8 BOM/no-BOM consistency with the embedded original to avoid view-precompilation drift.
- **`ContentTitle` reads from `IPageLayout.Content.Title`** — setting `ViewBag.Title` *does not* populate the `<h4>` heading, only the `<title>` element. Use `PageLayout.Content.Title = ...` (the page already injects `IPageLayout` if it uses the standard `_ViewImports.cshtml`).
- **The application layout always emits `ApplicationLocalizationScript`, `ApplicationConfigurationScript`, and `ServiceProxyScript`** — these endpoints can be expensive on cold start. If you serve thousands of anonymous landing-page requests per second, consider using the Empty layout for those pages (which still emits the same scripts, so the savings are limited; the right answer for unauthenticated landing pages is a separate non-ABP host).
- **The Account layout's tenant-switch panel relies on `ITenantResolveResultAccessor`**. If you replace the default `MultiTenancyMiddleware` with a custom resolver chain, ensure the chain produces the same `AppliedResolvers` collection or the panel will hide silently.
- **Bundle contributors run once per process** — they do not see changes to `wwwroot/themes/basic/layout.css` without restarting the host. If you customise the file via virtual-file overrides, the file watcher will pick it up; if you bundle externally, you must purge `IBundleManager`'s cache.
