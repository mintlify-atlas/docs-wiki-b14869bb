`@abp/aspnetcore.components.server.basictheme` is the npm side of ABP's open-source **Blazor Server
Basic theme**. It is the Blazor Server twin of
[`@abp/aspnetcore.mvc.ui.theme.basic`](/npm/aspnetcore-mvc-ui-theme-basic): both are tiny declarative
packs whose only job is to make sure their `theming` dependency is installed. The actual Basic theme
components (`MainLayout.razor`, `MainHeader.razor`, the sidebar, the footer) live in the .NET Razor
Class Library `Volo.Abp.AspNetCore.Components.Server.BasicTheme` and ship as embedded `_content/`
assets.

## Package metadata

```json
{
    "name": "@abp/aspnetcore.components.server.basictheme",
    "version": "7.4.0",
    "license": "LGPL-3.0",
    "dependencies": {
        "@abp/aspnetcore.components.server.theming": "~7.4.0"
    }
}
```

Single dependency. No JS, no CSS, no resource mapping.

## Files shipped to the browser

```text
@abp/aspnetcore.components.server.basictheme/
├── package.json
└── README.md
```

That is the entire tarball. As with the MVC Basic theme, the visible assets (`basic-theme.css`,
`MainLayout.razor`, `MainHeader.razor`, …) are embedded in the `Volo.Abp.AspNetCore.Components.Server.BasicTheme`
.NET assembly and served from `_content/Volo.Abp.AspNetCore.Components.Server.BasicTheme/`.

## How the theme reaches the browser

A Blazor Server host's startup wiring:

```csharp
[DependsOn(typeof(AbpAspNetCoreComponentsServerBasicThemeModule))]
public class MyAppBlazorModule : AbpModule { }
```

The basic-theme module registers `IThemeFactory<BasicTheme>` as the active theme and contributes a
`MainLayout` of type `Volo.Abp.AspNetCore.Components.Server.BasicTheme.Themes.Basic.MainLayout`. That
layout component references Bootstrap classes (`navbar`, `dropdown`, `btn`) and Font Awesome glyphs
(`<i class="fa fa-bars"></i>`). Both libraries are present in `wwwroot/libs/` because of the npm
chain documented in
[`@abp/aspnetcore.components.server.theming`](/npm/aspnetcore-components-server-theming).

A typical `_Host.cshtml` references:

```html
<link rel="stylesheet" href="_content/Volo.Abp.AspNetCore.Components.Server.BasicTheme/libs/bootstrap/css/bootstrap.min.css" />
<link rel="stylesheet" href="_content/Volo.Abp.AspNetCore.Components.Server.BasicTheme/libs/@fortawesome/fontawesome-free/css/all.min.css" />
<link rel="stylesheet" href="_content/Volo.Abp.AspNetCore.Components.Server.BasicTheme/themes/basic/basic.css" />

<script src="_framework/blazor.server.js"></script>
```

The host project's own `package.json` only needs to list this pack:

```json
{
    "dependencies": {
        "@abp/aspnetcore.components.server.basictheme": "~7.4.0"
    }
}
```

`abp install-libs` walks the dependency tree, finds `@abp/bootstrap` and `@abp/font-awesome` through
the `theming` pack, and populates `wwwroot/libs/`.

## What you get visually

The Basic Blazor Server theme produces an admin shell consisting of:

- A top **navbar** with the application name, language switcher (`<LanguageSwitchComponent />`), and
  user menu (`<UserMenuComponent />`).
- A collapsible **sidebar** populated from `IMenuManager` and the `ApplicationMenu` contributors.
- A **content area** with breadcrumbs and the routed page component.
- A **footer** with the ABP copyright (replaceable via Razor partial override).

None of this is in the npm package. The npm package only guarantees Bootstrap + Font Awesome are
copied to disk so the rendered HTML actually looks right.

## A minimal Blazor Server host that uses the Basic theme

```csharp
// MyApp.Blazor/MyAppBlazorModule.cs
[DependsOn(
    typeof(AbpAspNetCoreComponentsServerBasicThemeModule),
    typeof(MyAppApplicationModule),
    typeof(MyAppEntityFrameworkCoreModule)
)]
public class MyAppBlazorModule : AbpModule
{
    public override void ConfigureServices(ServiceConfigurationContext context)
    {
        Configure<AbpRouterOptions>(options =>
        {
            options.AppAssembly = typeof(MyAppBlazorModule).Assembly;
        });

        Configure<AbpThemingOptions>(options =>
        {
            options.DefaultThemeName = BasicTheme.Name;
        });
    }
}
```

```html
@* MyApp.Blazor/Pages/_Host.cshtml *@
@page "/"
@namespace MyApp.Blazor.Pages
<!DOCTYPE html>
<html lang="en">
<head>
    <base href="~/" />
    <link rel="stylesheet" href="_content/Volo.Abp.AspNetCore.Components.Server.BasicTheme/themes/basic/basic.css" />
</head>
<body>
    <component type="typeof(App)" render-mode="ServerPrerendered" />
    <script src="_framework/blazor.server.js"></script>
</body>
</html>
```

`App.razor` then routes through the `MainLayout` contributed by the Basic theme module.

## Razor (server) page example

The npm package has no code, so the only "Razor view example" worth writing is the chrome above. From
within an actual `.razor` page you do not interact with this pack at all — you write standard Blazor
markup and ABP's `<MainLayout>` (registered by the basic-theme NuGet) wraps it:

```razor
@page "/posts"
@inherits AbpComponentBase
@inject IPostAppService PostAppService

<Card>
    <CardHeader>
        <h2>Posts</h2>
    </CardHeader>
    <CardBody>
        <Table Striped>
            <TableHeader>
                <TableRow>
                    <TableHeaderCell>Title</TableHeaderCell>
                    <TableHeaderCell>Author</TableHeaderCell>
                </TableRow>
            </TableHeader>
            <TableBody>
                @foreach (var post in _posts)
                {
                    <TableRow>
                        <TableRowCell>@post.Title</TableRowCell>
                        <TableRowCell>@post.Author</TableRowCell>
                    </TableRow>
                }
            </TableBody>
        </Table>
    </CardBody>
</Card>

@code {
    private IReadOnlyList<PostDto> _posts = Array.Empty<PostDto>();

    protected override async Task OnInitializedAsync()
    {
        _posts = (await PostAppService.GetListAsync()).Items;
    }
}
```

The `Card`/`Table` components come from the chosen Blazor component library (Blazorise in the default
template); their default styling is Bootstrap, which is present thanks to this pack.

## Gotchas

- **The npm pack alone does not give you the theme.** You still need the matching NuGet packages
  (`Volo.Abp.AspNetCore.Components.Server.BasicTheme*`) and `[DependsOn(...)]` in your module.
- **Don't mix the MVC theme.basic and components.server.basictheme** unless you really need both
  surfaces. A single host project that exposes both MVC pages and Blazor Server pages can install
  both packs, but `wwwroot/libs/bootstrap/` becomes a shared resource — keep versions aligned.
- **Static-web-asset paths.** The `_content/<package>/` prefix can confuse webpack/vite if you import
  it through a JS bundler. Reference these files directly from `_Host.cshtml`, not from custom JS
  bundles.
- **No client-side `abp.*` global.** Blazor Server does not load `@abp/core`'s `abp.js`. If you have
  inline JS that calls `abp.notify.success(...)`, it will throw — use Blazor's
  `IUiNotificationService` from C# instead.
