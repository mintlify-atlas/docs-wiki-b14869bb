`@abp/utils` is the **odd one out** in the MVC/Razor-side npm packs: it is not a hand-written
`abp.js` extension and it is not a meta-package. It is a fully fledged **Angular library**, built with
`ng-packagr`, that compiles a typed TypeScript `LinkedList<T>` implementation down to UMD, ESM, and
TypeScript declaration files. Both the ABP Angular SDK and the MVC/Razor stack consume it, just via
different module formats.

## Package metadata

From `npm/packs/utils/package.json`:

```json
{
    "name": "@abp/utils",
    "version": "7.4.0",
    "main":    "dist/bundles/abp-utils.umd.js",
    "module":  "dist/fesm2015/abp-utils.js",
    "es2015":  "dist/fesm2015/abp-utils.js",
    "esm2015": "dist/esm2015/abp-utils.js",
    "typings": "dist/abp-utils.d.ts",
    "sideEffects": false
}
```

The `devDependencies` block pins Angular 10, `ng-packagr` 10, Jest 25, and `codelyzer` — the package
is built with a fixed historical toolchain even when newer Angular versions ship. That is intentional:
the published `dist/` artefacts must remain compatible with Angular projects scaffolded over the last
several major ABP releases.

The single runtime dependency is `just-compare`, used inside the linked-list comparison helpers.

## Files shipped to the browser

The published tarball contains a `dist/` directory generated by `ng-packagr`. The Razor-side resource
mapping only copies the **UMD bundle**:

```js
// npm/packs/utils/abp.resourcemapping.js
module.exports = {
    mappings: {
        '@node_modules/@abp/utils/dist/bundles/*.*': '@libs/abp/utils/',
    },
};
```

After `abp install-libs` you get:

```text
wwwroot/libs/abp/utils/
├── abp-utils.umd.js
└── abp-utils.umd.min.js
```

The UMD wrapper makes the same library available to:

- **AMD loaders** (`requirejs`).
- **CommonJS** (Node-side build tools).
- **Browser globals** — `window.ng.abp.utils.LinkedList`, which `@abp/core`'s ui-extensions module
  re-exposes as `abp.utils.common.LinkedList`.

The Angular consumer side picks up `dist/fesm2015/abp-utils.js` (the flat ES2015 module bundle) so the
Angular CLI's AOT compiler can tree-shake. Razor projects do not see those files — only the UMD.

## What's actually inside

The source lives at `npm/packs/utils/projects/utils/src/`:

```text
projects/utils/src/
├── public-api.ts                   ← export * from './lib/linked-list';
└── lib/
    ├── linked-list.ts              ← ~600 lines of LinkedList<T>
    └── linked-list.spec.ts         ← Jest test suite
```

`public-api.ts` is exactly one line:

```ts
export * from './lib/linked-list';
```

So today `@abp/utils` is **just a `LinkedList<T>`** — a doubly-linked, generic, fluently-typed list
plus a small set of `ListNode<T>` helpers. The intent of the package is to be a home for any future
data structures the Angular SDK and the MVC UI both need; for now the linked list is the only resident.

## The `LinkedList<T>` API

The exported types:

```ts
export class ListNode<T = any> {
    next:     ListNode | undefined;
    previous: ListNode | undefined;
    constructor(public readonly value: T) {}
}

export type ListComparisonFn<T> = (currentValue: T, soughtValue: T) => boolean;

export class LinkedList<T = any> {
    get head(): ListNode<T> | undefined;
    get tail(): ListNode<T> | undefined;
    get length(): number;

    add(value: T): {
        after:    (...params: [T] | [any, ListComparisonFn<T>]) => ListNode<T>;
        before:   (...params: [T] | [any, ListComparisonFn<T>]) => ListNode<T>;
        byIndex:  (position: number) => ListNode<T>;
        head:     () => ListNode<T>;
        tail:     () => ListNode<T>;
    };
    addMany(values: T[]): { /* same shape, but returns ListNode<T>[] */ };

    addAfter (value: T, previousValue: T | any, compareFn?: ListComparisonFn<T>): ListNode<T>;
    addBefore(value: T,     nextValue: T | any, compareFn?: ListComparisonFn<T>): ListNode<T>;
    addByIndex(value: T, position: number): ListNode<T>;
    addHead   (value: T): ListNode<T>;
    addTail   (value: T): ListNode<T>;

    find(predicate: (node: ListNode<T>) => boolean): ListNode<T> | undefined;
    indexOf(value: T, compareFn?: ListComparisonFn<T>): number;
    toArray(): T[];
    toNodeArray(): ListNode<T>[];

    drop(value: T | any, compareFn?: ListComparisonFn<T>): ListNode<T> | undefined;
    dropByIndex(position: number): ListNode<T> | undefined;
    dropHead(): ListNode<T> | undefined;
    dropTail(): ListNode<T> | undefined;
    clear(): void;
}
```

### The fluent `add(...)` builder

The unusual API shape:

```ts
const list = new LinkedList<number>();
list.add(1).head();
list.add(2).tail();
list.add(99).after(1);                  // 1, 99, 2
list.add(50).before(99);                // 1, 50, 99, 2
list.add(3).byIndex(0);                 // 3, 1, 50, 99, 2
```

`add(value)` returns an object whose methods finish the insertion. This avoids the classic
"`addAfter(value, after)` — which is which?" footgun.

### Comparison functions

When `T` is a complex object you typically can't insert "after the existing node whose value `==` x"
with reference equality. `@abp/utils` uses `just-compare` (deep equality) as the default `compareFn`,
and lets you override:

```ts
const users = new LinkedList<User>();
users.addTail({ id: 1, name: 'Alice' });
users.addTail({ id: 2, name: 'Bob'   });

const dummy = { id: 1 } as any;
users.addAfter({ id: 3, name: 'Carol' }, dummy,
    (a, b) => a.id === b.id);
// Order: Alice, Carol, Bob
```

`drop`, `indexOf`, and the `add(value).after/.before` variants all accept the same `compareFn`.

## How the MVC UI uses it

`@abp/aspnetcore.mvc.ui.theme.shared`'s `ui-extensions.js` builds entity action lists and column lists
on top of this exact `LinkedList`:

```js
// framework/.../wwwroot/libs/abp/aspnetcore-mvc-ui-theme-shared/ui-extensions.js
abp.ui.extensions.ActionList = function () {
    return new abp.utils.common.LinkedList();
};

abp.ui.extensions.ColumnList = function () {
    return new abp.utils.common.LinkedList();
};
```

The UMD bundle attaches `LinkedList` to the global UMD namespace, which `@abp/core`'s consumer wires
up as `abp.utils.common.LinkedList`. As an extension author you then do:

```js
abp.ui.extensions.entityActions.get('user').addContributor(function (actionList) {
    actionList.addTail({
        text: 'Lock User',
        action: function (data) {
            volo.abp.identity.identityUser.lock(data.record.id);
        },
        visible: function (data) { return !data.record.isLockedOut; }
    });
});
```

Ordering of the contributed action is decided by the linked list operations — `addHead` puts your
action first, `addTail` last, `before('Delete', (a, b) => a.text === b.text)` slots it before the
shipped Delete action.

## Razor view example

You rarely instantiate `LinkedList<T>` from a Razor `<script>` block directly — the MVC UI wraps it
under `abp.ui.extensions.*`. But the bundle is available, so you can:

```html
@page
<script src="~/libs/abp/utils/abp-utils.umd.js"></script>
<script>
    // The UMD bundle attaches under ng.abp.utils in pure-browser mode.
    var list = new abp.utils.common.LinkedList();
    list.addTail('first');
    list.addTail('second');
    console.log(list.toArray()); // ["first", "second"]
</script>
```

In practice the `<script>` tag is included by the
[`@abp/aspnetcore.mvc.ui.theme.shared`](/npm/aspnetcore-mvc-ui-theme-shared) bundle contributor, so
you never reference it explicitly.

## Gotchas

- **Don't update the Angular toolchain in this package** unless you intend to break older Angular
  consumers. The `devDependencies` are intentionally pinned to Angular 10.
- **`sideEffects: false`** — Angular CLI can tree-shake the ESM bundle aggressively. If you re-export
  from a different file in your own library, you must mark that file `sideEffects: false` as well or
  Webpack will conservatively keep everything.
- **Deep equality is not free**. `just-compare` traverses the whole value graph. Inserting into a list
  of 10,000 objects with `add(x).after(needle)` runs `compareFn` until it finds a match — pass a fast
  `(a, b) => a.id === b.id` rather than relying on the default.
- **The UMD bundle attaches to globals as `ng.abp.utils`**, not `abp.utils`. The bridge that exposes
  it as `abp.utils.common.LinkedList` is in `ui-extensions.js` from
  [`@abp/aspnetcore.mvc.ui.theme.shared`](/npm/aspnetcore-mvc-ui-theme-shared). If you only load
  `abp-utils.umd.js`, look under `ng.abp.utils.LinkedList`.
- **Don't confuse `abp.utils` with `abp.utils.common`.** `abp.utils.*` is the hand-written grab-bag
  from `@abp/core` (`formatString`, `replaceAll`, cookies). `abp.utils.common.*` is the namespace the
  MVC UI uses to attach exports of this Angular library.
