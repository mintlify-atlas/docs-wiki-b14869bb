`@abp/blogging` is the npm side of ABP's **open-source Blogging module** — the predecessor of CMS Kit
that still ships and is still actively used. The pack is purely declarative: four dependencies that
together cover the legacy blog's hero carousel, syntax-highlighted code blocks, Markdown editing, and
all the shared theme infrastructure it inherits from
[`@abp/aspnetcore.mvc.ui.theme.shared`](/npm/aspnetcore-mvc-ui-theme-shared).

The Blogging module is **not** the same as the CMS Kit's blog feature. CMS Kit's blog is a multi-blog,
multi-tag, multi-user-rated content surface; the standalone Blogging module is the simpler, older
single-blog product. They share no UI code.

## Package metadata

```json
{
    "name": "@abp/blogging",
    "version": "7.4.0",
    "license": "LGPL-3.0",
    "dependencies": {
        "@abp/aspnetcore.mvc.ui.theme.shared": "~7.4.0",
        "@abp/owl.carousel":                   "~7.4.0",
        "@abp/prismjs":                        "~7.4.0",
        "@abp/tui-editor":                     "~7.4.0"
    }
}
```

The dependency on `theme.shared` is deliberate: the Blogging module's admin pages use ABP's
`ModalManager`, DataTables extensions, `abpAjaxForm`, and the rest of the shared library. Public
pages only use a subset, but the pack pulls in everything to keep installation simple.

## Files shipped to the browser

```text
@abp/blogging/
├── package.json
└── README.md
```

No `src/`, no `abp.resourcemapping.js`. The blogging UI's JS lives in the .NET project
`Volo.Blogging.Web` under:

```text
src/Volo.Blogging.Web/Pages/Blogs/
├── Shared/Scripts/blog.js              ← hero carousel, helper functions
├── Posts/detail.js                     ← Prism highlight on post detail
├── Posts/edit.js                       ← TUI editor on the edit page
└── Posts/new.js                        ← TUI editor on the new post page
```

After `abp install-libs` you additionally get:

```text
wwwroot/libs/
├── owl.carousel/owl.carousel.min.{css,js}
├── prismjs/prism.{css,js}
└── tui-editor/tui-editor-full.min.{css,js}
```

## Where each dependency is used

### Owl Carousel — hero on the blog landing

From `Pages/Blogs/Shared/Scripts/blog.js`:

```js
(function () {
    function handleOwlCarousel() {
        $('.hero-section .owl-carousel').owlCarousel({
            loop:        true,
            margin:      0,
            nav:         false,
            dots:        false,
            autoplay:    true,
            autoHeight:  true,
            autoplaySpeed: 1000,
            items:       1
        });
        $('.card-article-container .owl-carousel').owlCarousel({
            loop:        true,
            margin:      0,
            nav:         false,
            dots:        false,
            autoplay:    true,
            autoplaySpeed: 1000,
            responsive: {
                0:    { items: 1 },
                600:  { items: 2 },
                1000: { items: 3 }
            }
        });
    }

    function handleArrows() {
        var herosWidth     = $('.hero-articles').width();
        var arrowsPosition = herosWidth / 2 - 90;
        $('.owl-next').css('right', arrowsPosition);
        $('.owl-prev').css('left',  arrowsPosition);
    }

    // public registration
    $(document).ready(function () { handleOwlCarousel(); handleArrows(); });
})();
```

`owlCarousel` is the jQuery plugin from **`@abp/owl.carousel`** — the underlying library is
[OwlCarousel2](https://owlcarousel2.github.io/OwlCarousel2/).

### Prism.js — syntax highlighting on post detail

`Pages/Blogs/Posts/detail.js` runs Prism over the rendered HTML:

```js
$(function () {
    Prism.highlightAll();
});
```

`Prism` is the global from **`@abp/prismjs`**. Prism's default theme `prism.css` is copied into
`wwwroot/libs/prismjs/`, but the admin can swap themes by mapping a different `prism-<theme>.css`
into the bundle contributor.

### TUI Editor — Markdown editing

The new/edit post pages mount the **Toast UI Editor** to compose Markdown:

```js
// Pages/Blogs/Posts/new.js
$(function () {
    var editor = new toastui.Editor({
        el: document.querySelector('#editor'),
        previewStyle: 'vertical',
        height: '500px',
        initialEditType: 'markdown',
        usageStatistics: false
    });

    $('#PostForm').on('submit', function () {
        $('#Post_Content').val(editor.getMarkdown());
    });
});
```

`toastui.Editor` is the global from **`@abp/tui-editor`**. The submit handler reads the editor body
into a hidden `<textarea>` named `Post_Content` so the standard model-binding picks it up.

## Razor view example

A blog post edit page that hosts the TUI editor:

```html
@page
@model EditPostModel

<form id="PostForm" method="post">
    <abp-input asp-for="Post.Title" />
    <abp-input asp-for="Post.UrlSlug" />

    <input type="hidden" asp-for="Post.Content" id="Post_Content" />
    <div id="editor"></div>

    <button type="submit" class="btn btn-primary">Save</button>
</form>

@section Scripts {
    <abp-script src="/Pages/Blogs/Posts/edit.js" />
}
```

The `<abp-script>` tag helper resolves to the static asset embedded by the Blogging module. The
required CSS for TUI Editor (`tui-editor-full.min.css`) is pulled in by the bundle contributor.

A public detail view:

```html
@page
@model PostDetailModel

<article class="blog-post">
    <h1>@Model.Post.Title</h1>
    <div class="post-content">
        @Html.Raw(Model.Post.RenderedHtml)
    </div>
</article>

@section Scripts {
    <abp-script src="/Pages/Blogs/Posts/detail.js" />
}
```

`detail.js` calls `Prism.highlightAll()` which walks every `<pre><code class="language-XXX">` block
in the rendered HTML and highlights it.

## Gotchas

- **Don't confuse with CMS Kit's blog.** The two coexist. If a project has both
  `Volo.Blogging.Web` and `Volo.CmsKit.Web` referenced, both packs will ship their own JS — the page
  you are looking at decides which globals matter.
- **TUI Editor v3 vs v2.** ABP currently ships TUI Editor v2-era globals (`toastui.Editor`). If a
  third-party plugin you add to a custom Razor page expects the v3 API (`toastui-editor`), they won't
  match. Pin compatible plugin versions.
- **Owl Carousel CSS depends on `owl.theme.default.min.css`.** Both files are copied by
  `@abp/owl.carousel`; verify the bundle contributor emits both `<link>` tags.
- **`Prism.highlightAll` is expensive on huge posts.** For pages with > 100 code blocks, prefer
  `Prism.highlightAllUnder(document.getElementById('post-content'))` to limit the scope.
- **The blog Markdown editor saves `markdown` text**; the public render uses the server-side Markdown
  pipeline. If you customise either, customise both — mismatches produce escaped or double-encoded
  output.
- **No public client proxy.** Unlike CMS Kit, the Blogging module's edit pages submit via Razor form
  posts (`<form method="post">`), not via `volo.*` client proxy calls. Don't try to call
  `volo.blogging.posts.*` from a custom widget; it doesn't exist on the public surface.
