---
title: "@abp/aspnetcore.components.server.theming"
description: "Blazor Server theming base pack — pulls in Bootstrap and Font Awesome via abp-resource-mapping so the wwwroot of a Blazor Server host has the assets the theme components expect."
---

`@abp/aspnetcore.components.server.theming` is the Blazor Server analogue of
[`@abp/aspnetcore.mvc.ui.theme.shared`](/npm/aspnetcore-mvc-ui-theme-shared) — but much simpler.
Blazor Server applications render mostly via `RenderTree` updates and SignalR rather than full Razor
views, so they need far fewer browser libraries than an MVC app. This pack guarantees that two static
asset families — **Bootstrap** and **Font Awesome** — are present, because both the open-source
`Volo.Abp.AspNetCore.Components.Server.BasicTheme` and the commercial LeptonX theme components depend
on Bootstrap CSS classes and Font Awesome glyphs.

## Package metadata

```json
{
    "name": "@abp/aspnetcore.components.server.theming",
    "version": "7.4.0",
    "license": "LGPL-3.0",
    "dependencies": {
        "@abp/bootstrap":     "~7.4.0",
        "@abp/font-awesome":  "~7.4.0"
    }
}
```

Just two dependencies. No JavaScript of its own.

## Files shipped to the browser

The npm package contains:

```text
@abp/aspnetcore.components.server.theming/
├── package.json
└── README.md
```

That's it. No `src/`, no `abp.resourcemapping.js`. The pack is a **declaration of dependencies** that
exists so a Blazor Server host can write

```json
{ "dependencies": { "@abp/aspnetcore.components.server.theming": "~7.4.0" } }
```

and, after `abp install-libs`, find Bootstrap and Font Awesome under `wwwroot/libs/`.

## How it interacts with Blazor Server

A Blazor Server `_Host.cshtml` (or `App.razor` in .NET 8+) typically references:

```html
<link rel="stylesheet" href="_content/Volo.Abp.AspNetCore.Components.Server.BasicTheme/libs/bootstrap/css/bootstrap.min.css" />
<link rel="stylesheet" href="_content/Volo.Abp.AspNetCore.Components.Server.BasicTheme/libs/@fortawesome/fontawesome-free/css/all.min.css" />
<link rel="stylesheet" href="_content/Volo.Abp.AspNetCore.Components.Server.BasicTheme/theme/basic-theme.css" />

<script src="_framework/blazor.server.js"></script>
```

The `_content/<package>` prefix is the convention ASP.NET Core uses to serve static files embedded in
a Razor Class Library. The Razor Class Library's `wwwroot/libs/` is populated using exactly the same
`abp.resourcemapping.js` mechanism as MVC projects — and that mechanism walks `@abp/bootstrap` and
`@abp/font-awesome` because they are declared here.

If you ever wonder *why* the `Volo.Abp.AspNetCore.Components.Server.BasicTheme` RCL contains a
`wwwroot/libs/bootstrap/css/bootstrap.min.css`, the answer is: because the RCL's `package.json`
includes `@abp/aspnetcore.components.server.theming` as a dependency, and the RCL ran `abp install-libs`
during its build, and this pack pulled in `@abp/bootstrap`, and `@abp/bootstrap`'s `abp.resourcemapping.js`
copied `bootstrap.min.css` into `wwwroot/libs/bootstrap/css/`.

## What's *not* here

Compared to `@abp/aspnetcore.mvc.ui.theme.shared`, this pack deliberately omits:

| Missing from this pack       | Why                                                           |
| ---------------------------- | ------------------------------------------------------------- |
| jQuery + jquery-form         | Blazor Server doesn't post forms via AJAX — it uses SignalR.  |
| jquery-validation-unobtrusive| Blazor uses `EditForm` + `DataAnnotationsValidator`.          |
| DataTables                   | Replaced by `DataGrid` from the chosen Blazor component lib.  |
| Toastr / SweetAlert2         | Blazor toasts and modals come from `IUiNotificationService`, `IUiMessageService`, rendered as Blazor components. |
| Select2, daterangepicker     | Replaced by component-library equivalents.                    |
| Luxon / moment / timeago     | C# `DateTime` formatting on the server; no per-browser JS.    |

Bootstrap stays because the Basic theme RCL renders Bootstrap markup (`btn`, `card`, `dropdown`, …).
Font Awesome stays because every icon in the chrome (sidebar collapse arrow, toolbar buttons,
breadcrumbs) is `<i class="fa fa-..."></i>`.

## Razor view example

Blazor Server hosts barely use Razor pages, but their `_Host.cshtml` does:

```html
@page "/"
@namespace MyApp.Blazor.Pages
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers

<!DOCTYPE html>
<html lang="en">
<head>
    <base href="~/" />

    @* Pulled in via @abp/bootstrap → abp install-libs *@
    <link rel="stylesheet" href="libs/bootstrap/css/bootstrap.min.css" />

    @* Pulled in via @abp/font-awesome *@
    <link rel="stylesheet" href="libs/@fortawesome/fontawesome-free/css/all.min.css" />

    @* Basic theme's own additional CSS *@
    <link rel="stylesheet" href="theme/basic-theme.css" />
</head>
<body>
    <component type="typeof(App)" render-mode="ServerPrerendered" />
    <script src="_framework/blazor.server.js"></script>
</body>
</html>
```

The two `libs/` references work only because `@abp/bootstrap` and `@abp/font-awesome` were transitively
installed via this package and `abp install-libs` populated `wwwroot/libs/` accordingly.

## Gotchas

- **Don't include this in an MVC `package.json`.** The MVC stack already pulls Bootstrap and Font
  Awesome via `@abp/aspnetcore.mvc.ui.theme.shared`; adding this pack duplicates nothing in code but
  bloats the lockfile and confuses future readers.
- **No `abp.notify` / `abp.message` bodies here.** Those APIs are MVC concepts; for Blazor Server you
  inject `IUiNotificationService.Notify(NotificationType.Info, "Saved")` from C# instead.
- **Versions must match the BasicTheme RCL.** `@abp/aspnetcore.components.server.basictheme` depends
  on this pack at `~7.4.0`. If your `package.json` pins a different patch, npm dedupe may pick the
  newer one and the RCL's compiled bundle expectations could drift.
- **Blazor WebAssembly hosts use a different pack.** This pack is server-side only; WebAssembly hosts
  use `@abp/aspnetcore.components.web.theming` (not documented here).
- **`abp install-libs` must run inside the Razor Class Library project**, not the host. The RCL is
  what embeds the static files; the host references them via `_content/<rcl>/`.
