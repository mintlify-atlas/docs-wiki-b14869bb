ABP ships a polling-based background-job system that stores serialized arguments in an `IBackgroundJobStore` and runs them on a periodic `IBackgroundJobWorker`. The default store is in-memory; the `Volo.Abp.BackgroundJobs.Domain` module replaces it with EF Core / MongoDB. Each job dispatch flows through `BackgroundJobExecuter`, which controls the tenant scope, exception notification, and retry calculation.

## Sequence

```mermaid
sequenceDiagram
    participant Caller
    participant Manager as DefaultBackgroundJobManager
    participant Store as IBackgroundJobStore
    participant Worker as BackgroundJobWorker
    participant Lock as IAbpDistributedLock
    participant Executer as BackgroundJobExecuter
    participant Tenant as ICurrentTenant
    participant Job as IAsyncBackgroundJob&lt;TArgs&gt;
    participant Notifier as IExceptionNotifier

    Caller->>Manager: EnqueueAsync(args, priority, delay)
    Manager->>Store: InsertAsync(BackgroundJobInfo)
    Store-->>Manager: Id (Guid)
    Manager-->>Caller: jobId
    Note over Worker: AsyncPeriodicBackgroundWorkerBase ticks every JobPollPeriod
    Worker->>Lock: TryAcquireAsync("AbpBackgroundJobWorker")
    Worker->>Store: GetWaitingJobsAsync(MaxJobFetchCount)
    loop each BackgroundJobInfo
        Worker->>Store: TryCount++; LastTryTime = now
        Worker->>Executer: ExecuteAsync(JobExecutionContext)
        Executer->>Tenant: Change(GetJobArgsTenantId(args))
        Executer->>Job: ExecuteAsync(args) or Execute(args)
        alt success
            Executer-->>Worker: completed
            Worker->>Store: DeleteAsync(jobInfo.Id)
        else exception
            Executer->>Notifier: NotifyAsync(ExceptionNotificationContext)
            Executer-->>Worker: throws BackgroundJobExecutionException
            Worker->>Worker: CalculateNextTryTime
            Worker->>Store: UpdateAsync(jobInfo) (IsAbandoned?)
        end
    end
```

## Step-by-step walk-through

1. **Enqueue.** Callers use `IBackgroundJobManager.EnqueueAsync<TArgs>(args, priority, delay)` (`framework/src/Volo.Abp.BackgroundJobs.Abstractions/Volo/Abp/BackgroundJobs/IBackgroundJobManager.cs`). The default implementation `DefaultBackgroundJobManager` (`framework/src/Volo.Abp.BackgroundJobs/Volo/Abp/BackgroundJobs/DefaultBackgroundJobManager.cs`) resolves the job name and persists a `BackgroundJobInfo`:
   ```csharp
   var jobName = BackgroundJobNameAttribute.GetName<TArgs>();
   var jobInfo = new BackgroundJobInfo {
       Id = GuidGenerator.Create(),
       JobName = jobName,
       JobArgs = Serializer.Serialize(args),
       Priority = priority,
       CreationTime = Clock.Now,
       NextTryTime = Clock.Now
   };
   if (delay.HasValue) jobInfo.NextTryTime = Clock.Now.Add(delay.Value);
   await Store.InsertAsync(jobInfo);
   return jobInfo.Id.ToString();
   ```
   The `BackgroundJobNameAttribute` (`framework/src/Volo.Abp.BackgroundJobs.Abstractions/Volo/Abp/BackgroundJobs/BackgroundJobNameAttribute.cs`) on the args class supplies the canonical name; the fallback is `typeof(TArgs).FullName`.

2. **Job configuration.** `AbpBackgroundJobOptions` (`framework/src/Volo.Abp.BackgroundJobs.Abstractions/Volo/Abp/BackgroundJobs/AbpBackgroundJobOptions.cs`) maps each args type to a `BackgroundJobConfiguration { JobType, ArgsType, JobName }`. Modules call `options.AddJob<MyJobArgs>(typeof(MyJob))` during `ConfigureServices`. `IsJobExecutionEnabled = false` disables execution (used during database migrations — `AbpBackgroundJobsModule.ConfigureServices` flips it off when `services.IsDataMigrationEnvironment()` is true).

3. **Store implementations.**
   - `InMemoryBackgroundJobStore` (`framework/src/Volo.Abp.BackgroundJobs/Volo/Abp/BackgroundJobs/InMemoryBackgroundJobStore.cs`) keeps a `ConcurrentDictionary<Guid, BackgroundJobInfo>`. `GetWaitingJobsAsync` orders by priority descending, then `TryCount` ascending, then `NextTryTime` ascending.
   - The DB-backed store from `Volo.Abp.BackgroundJobs.Domain` (`modules/background-jobs/src/Volo.Abp.BackgroundJobs.Domain/...`) uses `IBackgroundJobRepository` and adds row-level locking.

4. **Worker registration.** `AbpBackgroundJobsModule.OnApplicationInitializationAsync` (`framework/src/Volo.Abp.BackgroundJobs/Volo/Abp/BackgroundJobs/AbpBackgroundJobsModule.cs`) registers the worker only when execution is enabled:
   ```csharp
   if (options.IsJobExecutionEnabled)
       await context.AddBackgroundWorkerAsync<IBackgroundJobWorker>();
   ```
   `IBackgroundWorkerManager` (from `Volo.Abp.BackgroundWorkers`) starts the worker as a hosted service.

5. **Periodic loop.** `BackgroundJobWorker` (`framework/src/Volo.Abp.BackgroundJobs/Volo/Abp/BackgroundJobs/BackgroundJobWorker.cs`) extends `AsyncPeriodicBackgroundWorkerBase` and sets `Timer.Period = WorkerOptions.JobPollPeriod` (default 5000 ms from `AbpBackgroundJobWorkerOptions`).

6. **Distributed lock.** On each tick `DoWorkAsync`:
   ```csharp
   await using (var handler = await DistributedLock.TryAcquireAsync(DistributedLockName, cancellationToken: StoppingToken))
   {
       if (handler != null) { ... }
       else { await Task.Delay(WorkerOptions.JobPollPeriod * 12, StoppingToken); }
   }
   ```
   The lock name is `"AbpBackgroundJobWorker"`. When the lock cannot be acquired (another instance is processing), the worker sleeps 12× the poll period to back off.

7. **Fetch.** With the lock held, the worker resolves the per-tick dependencies (store, executer, clock, serializer) from `workerContext.ServiceProvider` and calls `store.GetWaitingJobsAsync(WorkerOptions.MaxJobFetchCount)`. Default `MaxJobFetchCount` is 1000.

8. **Per-job loop.** For every `BackgroundJobInfo`:
   ```csharp
   jobInfo.TryCount++;
   jobInfo.LastTryTime = clock.Now;
   try {
       var jobConfiguration = JobOptions.GetJob(jobInfo.JobName);
       var jobArgs = serializer.Deserialize(jobInfo.JobArgs, jobConfiguration.ArgsType);
       var context = new JobExecutionContext(workerContext.ServiceProvider, jobConfiguration.JobType, jobArgs, workerContext.CancellationToken);
       try { await jobExecuter.ExecuteAsync(context); await store.DeleteAsync(jobInfo.Id); }
       catch (BackgroundJobExecutionException) {
           var nextTryTime = CalculateNextTryTime(jobInfo, clock);
           if (nextTryTime.HasValue) jobInfo.NextTryTime = nextTryTime.Value;
           else jobInfo.IsAbandoned = true;
           await TryUpdateAsync(store, jobInfo);
       }
   } catch (Exception ex) {
       Logger.LogException(ex);
       jobInfo.IsAbandoned = true;
       await TryUpdateAsync(store, jobInfo);
   }
   ```

9. **`BackgroundJobExecuter.ExecuteAsync`.** (`framework/src/Volo.Abp.BackgroundJobs.Abstractions/Volo/Abp/BackgroundJobs/BackgroundJobExecuter.cs`) resolves the job and invokes the right method:
   ```csharp
   var job = context.ServiceProvider.GetService(context.JobType);
   if (job == null) throw new AbpException("The job type is not registered to DI: " + context.JobType);
   var jobExecuteMethod = context.JobType.GetMethod(nameof(IBackgroundJob<object>.Execute))
                       ?? context.JobType.GetMethod(nameof(IAsyncBackgroundJob<object>.ExecuteAsync));
   if (jobExecuteMethod == null) throw new AbpException(...);
   try
   {
       using (CurrentTenant.Change(GetJobArgsTenantId(context.JobArgs)))
       using (cancellationTokenProvider.Use(context.CancellationToken))
       {
           if (jobExecuteMethod.Name == nameof(IAsyncBackgroundJob<object>.ExecuteAsync))
               await ((Task)jobExecuteMethod.Invoke(job, new[] { context.JobArgs })!);
           else jobExecuteMethod.Invoke(job, new[] { context.JobArgs });
       }
   }
   catch (Exception ex)
   {
       Logger.LogException(ex);
       await context.ServiceProvider.GetRequiredService<IExceptionNotifier>().NotifyAsync(new ExceptionNotificationContext(ex));
       throw new BackgroundJobExecutionException("A background job execution is failed. See inner exception for details.", ex)
       { JobType = context.JobType.AssemblyQualifiedName!, JobArgs = context.JobArgs };
   }
   ```

10. **Tenant scope.** `GetJobArgsTenantId(args)` returns `args.TenantId` when `args` implements `IMultiTenant`; otherwise the current tenant (which is normally null in the worker thread). Wrapping `CurrentTenant.Change` makes downstream `MultiTenantConnectionStringResolver`, repositories, and authorization checks see the originating tenant.

11. **Cancellation propagation.** `ICancellationTokenProvider.Use(context.CancellationToken)` pushes the worker's `StoppingToken` so `IAsyncBackgroundJob`s can poll it via `CancellationTokenProvider.Token`.

12. **Retry math.** `BackgroundJobWorker.CalculateNextTryTime`:
    ```csharp
    var nextWaitDuration = WorkerOptions.DefaultFirstWaitDuration * Math.Pow(WorkerOptions.DefaultWaitFactor, jobInfo.TryCount - 1);
    var nextTryDate = jobInfo.LastTryTime?.AddSeconds(nextWaitDuration) ?? clock.Now.AddSeconds(nextWaitDuration);
    if (nextTryDate.Subtract(jobInfo.CreationTime).TotalSeconds > WorkerOptions.DefaultTimeout) return null;
    return nextTryDate;
    ```
    Defaults: first wait 60 s, factor 2.0, timeout 172,800 s (2 days). Returning `null` marks the job as `IsAbandoned`.

13. **Alternate engines.** The Hangfire (`framework/src/Volo.Abp.BackgroundJobs.HangFire/...`), Quartz (`Volo.Abp.BackgroundJobs.Quartz`) and RabbitMQ (`Volo.Abp.BackgroundJobs.RabbitMQ`) modules replace `IBackgroundJobManager` and `IBackgroundJobWorker` with their own implementations. The job contract — `IBackgroundJob<TArgs>` / `IAsyncBackgroundJob<TArgs>` — is the same.

## Gotchas

- **In-memory store loses jobs on restart.** The default `InMemoryBackgroundJobStore` is registered as a singleton with a `ConcurrentDictionary`. Production setups must reference `Volo.Abp.BackgroundJobs.Domain` and a DB provider.
- **`IsJobExecutionEnabled` defaults to true.** Long-running migration scripts that boot the application module graph should set `services.AddDataMigrationEnvironment()` (which flips the flag off) to avoid the worker competing for the DB.
- **Args must round-trip through the serializer.** `IBackgroundJobSerializer` defaults to `JsonBackgroundJobSerializer`. Streams, interfaces, and abstract types throw at deserialize.
- **Tenant comes from args.** If your args class doesn't implement `IMultiTenant`, the job runs in the worker process's *current* tenant — usually null/host. Failing to declare it causes silent cross-tenant data writes.
- **`CurrentPrincipalAccessor.Principal` is not set.** Background jobs run anonymously. Authorization checks inside a job will fail unless you wrap with `ICurrentPrincipalAccessor.Change(...)`.
- **Abandoned jobs stay in the table.** Rows with `IsAbandoned = true` are not auto-deleted; long-running deployments need a cleanup task (the DB store ships one via a periodic worker; the in-memory store doesn't).
- **Cancellation is cooperative.** `JobExecutionContext.CancellationToken` is the host's `StoppingToken`. Tight CPU loops won't honor it unless the job checks the token.
- **Distributed lock false negative.** With many low-priority jobs, the 12× back-off after a missed lock can starve the queue for minutes. Tune `JobPollPeriod` and `MaxJobFetchCount` together.
