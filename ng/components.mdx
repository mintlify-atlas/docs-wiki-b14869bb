`@abp/ng.components` is a *multi-entry* Angular library. The root `public-api.ts` is empty on purpose — every UI primitive lives in its own [secondary entry point](https://angular.dev/tools/libraries/angular-package-format) under sibling directories. This keeps tree-shaking effective when an app only needs one or two of the pieces.

The package targets Angular 16 and depends on `ng-zorro-antd` (used by `tree`) and `chart.js` (used by `chart.js`). It peer-depends on `@abp/ng.core` and `@abp/ng.theme.shared`.

The empty primary entry is intentional:

```typescript
// packages/components/src/public-api.ts
/*
 * Public API Surface of components
 */

export {};
```

Importing from `@abp/ng.components` directly will give you nothing. You always import from a secondary entry such as `@abp/ng.components/page`.

## Why three sub-packages?

| Sub-package | npm import | Pulls in |
| ----------- | ---------- | -------- |
| `page` | `@abp/ng.components/page` | nothing extra |
| `tree` | `@abp/ng.components/tree` | `ng-zorro-antd/tree`, `@ng-bootstrap/ng-bootstrap` |
| `chart.js` | `@abp/ng.components/chart.js` | lazy-loaded `chart.js` (loaded at runtime) |

ng-packagr's `ng-package.json` files declare them in `allowedNonPeerDependencies` so they are not flagged at build time.

## `@abp/ng.components/page`

The `PageComponent` is the wrapper every administrative screen uses to render title, breadcrumb, optional toolbar and a content area. Its public-api exposes:

```typescript
// packages/components/page/src/public-api.ts
export * from './page.module';
export * from './page-part.directive';
export * from './page-parts.component';
export * from './page.component';
```

`PageComponent`:

```typescript
// packages/components/page/src/page.component.ts
@Component({
  selector: 'abp-page',
  templateUrl: './page.component.html',
  encapsulation: ViewEncapsulation.None,
})
export class PageComponent {
  @Input() title?: string;

  toolbarVisible = false;
  _toolbarData: any;
  @Input() set toolbar(val: any) {
    this._toolbarData = val;
    this.toolbarVisible = true;
  }

  get toolbarData() { return this._toolbarData; }

  @Input() breadcrumb = true;

  pageParts = {
    title: PageParts.title,
    breadcrumb: PageParts.breadcrumb,
    toolbar: PageParts.toolbar,
  };

  @ContentChild(PageTitleContainerComponent) customTitle?: PageTitleContainerComponent;
  @ContentChild(PageBreadcrumbContainerComponent) customBreadcrumb?: PageBreadcrumbContainerComponent;
  @ContentChild(PageToolbarContainerComponent) customToolbar?: PageToolbarContainerComponent;

  get shouldRenderRow() {
    return !!(
      this.title || this.toolbarVisible || this.breadcrumb ||
      this.customTitle || this.customBreadcrumb || this.customToolbar
    );
  }
}
```

### Basic usage

```html
<abp-page title="::Roles" [toolbar]="toolbar">
  <ng-template #toolbar>
    <button class="btn btn-primary" (click)="createRole()">
      <i class="fa fa-plus"></i> {{ '::NewRole' | abpLocalization }}
    </button>
  </ng-template>

  <ngx-datatable [rows]="data" abpNgxDatatableDefault>
    <!-- columns -->
  </ngx-datatable>
</abp-page>
```

### Slot overrides via `PageParts`

If you need full control of one slot, project a `<abp-page-toolbar-container>` or `<abp-page-title-container>`:

```html
<abp-page>
  <abp-page-title-container>
    <h2>{{ widget.name }}</h2>
    <small>{{ widget.createdAt | date }}</small>
  </abp-page-title-container>

  <abp-page-toolbar-container>
    <button class="btn btn-secondary">Refresh</button>
  </abp-page-toolbar-container>

  <ng-template abpPagePart="content">…</ng-template>
</abp-page>
```

The `PagePartDirective` (selector `[abpPagePart]`) flags which slot a `<ng-template>` belongs to.

## `@abp/ng.components/tree`

A wrapper around `ng-zorro-antd/tree` that adds ABP's loading strategy, drop-position calculation and contextual menu pattern.

```typescript
// packages/components/tree/src/public-api.ts
export * from './lib/tree.module';
export * from './lib/components/tree.component';
export * from './lib/utils/nz-tree-adapter';
export * from './lib/templates/tree-node-template.directive';
export * from './lib/templates/expanded-icon-template.directive';
export * from './lib/disable-tree-style-loading.token';
```

`TreeComponent`:

```typescript
// packages/components/tree/src/lib/components/tree.component.ts (excerpt)
@Component({
  selector: 'abp-tree',
  templateUrl: 'tree.component.html',
  styleUrls: ['tree.component.scss'],
  encapsulation: ViewEncapsulation.None,
  providers: [SubscriptionService],
  changeDetection: ChangeDetectionStrategy.OnPush,
})
export class TreeComponent implements OnInit {
  dropPosition: number;
  dropdowns = {} as { [key: string]: NgbDropdown };

  constructor(
    private lazyLoadService: LazyLoadService,
    private subscriptionService: SubscriptionService,
    @Optional() @Inject(DISABLE_TREE_STYLE_LOADING_TOKEN)
    private disableTreeStyleLoading: boolean | undefined,
    private cdr: ChangeDetectorRef,
  ) {}

  @ContentChild('menu') menu: TemplateRef<any>;
  @ContentChild(TreeNodeTemplateDirective) customNodeTemplate: TreeNodeTemplateDirective;
  @ContentChild(ExpandedIconTemplateDirective) expandedIconTemplate: ExpandedIconTemplateDirective;

  @Output() readonly checkedKeysChange = new EventEmitter();
  @Output() readonly expandedKeysChange = new EventEmitter<string[]>();
  @Output() readonly selectedNodeChange = new EventEmitter();
  @Output() readonly dropOver = new EventEmitter<DropEvent>();
  @Output() readonly nzExpandChange = new EventEmitter<NzFormatEmitEvent>();

  @Input() noAnimation = true;
  @Input() draggable: boolean;
  @Input() checkable: boolean;
  @Input() checkStrictly: boolean;
  @Input() checkedKeys = [];
  @Input() nodes = [];
  /* … */
}
```

### Lazy style loading

By default the component injects the ng-zorro CSS lazily through `LazyLoadService` to avoid bundling it. Inject `DISABLE_TREE_STYLE_LOADING_TOKEN = true` if you already ship the styles globally.

### Adapter helper

`nz-tree-adapter` maps a flat `{ id, parentId, displayName }` list into the nested shape ng-zorro expects:

```typescript
import { NzTreeAdapter } from '@abp/ng.components/tree';

const nodes = new NzTreeAdapter(flatList, 'id', 'parentId').toTree();
```

### Custom node template

```html
<abp-tree [nodes]="nodes" checkable [checkedKeys]="checked"
          (checkedKeysChange)="checked = $event">
  <ng-template abpTreeNodeTemplate let-node>
    <i class="fa fa-folder"></i> {{ node.title }}
  </ng-template>
</abp-tree>
```

## `@abp/ng.components/chart.js`

A skinny wrapper around the [`chart.js`](https://www.chartjs.org/) library. The library file is loaded at runtime so applications that don't render charts pay zero bundle cost:

```typescript
// packages/components/chart.js/src/chart.component.ts (excerpt)
let Chart: any;

@Component({
  selector: 'abp-chart',
  template: `
    <div style="position:relative"
         [style.width]="responsive && !width ? null : width"
         [style.height]="responsive && !height ? null : height">
      <canvas #canvas
              [attr.width]="responsive && !width ? null : width"
              [attr.height]="responsive && !height ? null : height"
              (click)="onCanvasClick($event)"></canvas>
    </div>
  `,
  changeDetection: ChangeDetectionStrategy.OnPush,
  exportAs: 'abpChart',
})
export class ChartComponent implements AfterViewInit, OnDestroy, OnChanges {
  @Input() type!: string;
  @Input() data: any = {};
  /* … */
}
```

`widget-utils.ts` ships helpers for the widget framework used by ABP Commercial dashboards (`buildChartOptions`, `mergeDatasetColors`).

### Usage

```typescript
import { Component } from '@angular/core';
import { ChartModule } from '@abp/ng.components/chart.js';

@Component({
  selector: 'app-tenants-chart',
  template: `<abp-chart type="bar" [data]="data" [options]="options"></abp-chart>`,
})
export class TenantsChartComponent {
  data = {
    labels: ['Jan', 'Feb', 'Mar'],
    datasets: [{ label: 'Tenants', data: [10, 15, 22] }],
  };
  options = { responsive: true };
}
```

```typescript
@NgModule({ imports: [ChartModule], declarations: [TenantsChartComponent] })
export class DashboardModule {}
```

`Chart` is loaded the first time the component initialises — subsequent instances reuse the cached module via `LazyLoadService`.

## Importing rules

Always import from a secondary entry; never from the package root:

```typescript
import { PageModule, PageComponent }     from '@abp/ng.components/page';
import { TreeModule, NzTreeAdapter }     from '@abp/ng.components/tree';
import { ChartModule, ChartComponent }   from '@abp/ng.components/chart.js';
```

`@abp/ng.identity`, `@abp/ng.tenant-management`, and the LeptonX themes already declare `PageModule` for their administrative screens — you don't need to add it again if you only consume those modules.

## Peer dependency matrix

```json
// packages/components/package.json
{
  "peerDependencies": {
    "@abp/ng.core":          ">=7.4.0",
    "@abp/ng.theme.shared":  ">=7.4.0"
  },
  "dependencies": {
    "chart.js":      "^3.5.1",
    "ng-zorro-antd": "^16.0.0",
    "tslib":         "^2.0.0"
  }
}
```

`chart.js` and `ng-zorro-antd` are listed as direct dependencies but the entry points are split so they only end up in your bundle if you import the relevant secondary entry.

## Gotchas

* Importing `@abp/ng.components` (without a sub-path) yields `{}` and a wasted require — the root is deliberately empty.
* `abp-tree` requires the `<NgbDropdown>` module from `@ng-bootstrap/ng-bootstrap` to be available for the contextual menu — it is re-exported by `ThemeSharedModule`.
* `abp-chart` does **not** ship type definitions for chart.js options on the `[options]` input — type them yourself if you want strict checks.
* The `[toolbar]` input on `<abp-page>` accepts a `TemplateRef` *or* any truthy value; passing a string still flips `toolbarVisible` to `true` and renders an empty slot.
* When the tree is `draggable`, you must handle `(dropOver)` and apply the new order yourself — the component only emits events, it doesn't mutate the input array.
