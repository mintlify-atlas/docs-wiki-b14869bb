`@abp/ng.theme.basic` ships the *basic* ABP theme — a clean Bootstrap layout used by the framework's starter templates when neither LeptonX nor a custom theme is selected. It implements the three required ABP layouts (application, account, empty), wires the nav-items / user-menu registries from `@abp/ng.theme.shared`, and provides validation error templates plus lazy-loaded styles.

## ThemeBasicModule.forRoot

```typescript
// packages/theme-basic/src/lib/theme-basic.module.ts (excerpt)
export const LAYOUTS = [
  ApplicationLayoutComponent,
  AccountLayoutComponent,
  EmptyLayoutComponent,
];

@NgModule({
  declarations: [
    ...LAYOUTS,
    ValidationErrorComponent,
    LogoComponent,
    NavItemsComponent,
    RoutesComponent,
    CurrentUserComponent,
    LanguagesComponent,
    PageAlertContainerComponent,
    TenantBoxComponent,
    AuthWrapperComponent,
  ],
  exports: [
    ...LAYOUTS,
    /* + slot components */
  ],
  imports: [CoreModule, ThemeSharedModule, NgbCollapseModule, NgbDropdownModule, NgxValidateCoreModule],
})
export class BaseThemeBasicModule {}

@NgModule({ exports: [BaseThemeBasicModule], imports: [BaseThemeBasicModule] })
export class ThemeBasicModule {
  static forRoot(): ModuleWithProviders<ThemeBasicModule> {
    return {
      ngModule: ThemeBasicModule,
      providers: [
        BASIC_THEME_NAV_ITEM_PROVIDERS,
        BASIC_THEME_USER_MENU_PROVIDERS,
        BASIC_THEME_STYLES_PROVIDERS,
        { provide: VALIDATION_ERROR_TEMPLATE, useValue: ValidationErrorComponent },
        { provide: VALIDATION_TARGET_SELECTOR, useValue: '.form-group' },
        { provide: VALIDATION_INVALID_CLASSES, useValue: 'is-invalid' },
        LazyStyleHandler,
        { provide: APP_INITIALIZER, useFactory: noop, multi: true, deps: [LazyStyleHandler] },
      ],
    };
  }
}
```

What `forRoot()` does:

1. Registers the *Languages*, *Current user* nav items via `BASIC_THEME_NAV_ITEM_PROVIDERS`.
2. Registers the *Manage profile*, *Sign out* entries via `BASIC_THEME_USER_MENU_PROVIDERS`.
3. Lazy-loads Bootstrap CSS (and theme overrides) via `LazyStyleHandler`.
4. Wires `@ngx-validate/core` to the basic theme's `ValidationErrorComponent` so all invalid inputs get the standard *form-control / is-invalid* visual treatment.

```typescript
// packages/theme-basic/src/lib/components/application-layout/application-layout.component.ts
@Component({
  selector: 'abp-layout-application',
  templateUrl: './application-layout.component.html',
  animations: [slideFromBottom, collapseWithMargin],
  providers: [LayoutService, SubscriptionService],
})
export class ApplicationLayoutComponent implements AfterViewInit {
  static type = eLayoutType.application; // required by DynamicLayoutComponent

  constructor(public service: LayoutService) {}

  ngAfterViewInit() {
    this.service.subscribeWindowSize();
  }
}
```

The static `type = eLayoutType.application` is how `DynamicLayoutComponent` (from `@abp/ng.core`) picks this layout for routes whose `data.layout` matches. `LayoutService` exposes responsive helpers (`isCollapsed$`, `windowSize$`).

## NavItemsComponent

```typescript
// packages/theme-basic/src/lib/components/nav-items/nav-items.component.ts
@Component({
  selector: 'abp-nav-items',
  templateUrl: 'nav-items.component.html',
})
export class NavItemsComponent {
  trackByFn: TrackByFunction<NavItem> = (_, element) => element.id;

  constructor(public readonly navItems: NavItemsService) {}
}
```

The template iterates over `navItems.items$` and renders each item's template. `LanguagesComponent` and `CurrentUserComponent` register themselves via `BASIC_THEME_NAV_ITEM_PROVIDERS` so they show up automatically:

```typescript
// providers/nav-item.provider.ts (excerpt)
export const BASIC_THEME_NAV_ITEM_PROVIDERS = [{
  provide: APP_INITIALIZER,
  useFactory: registerBasicNavItems,
  deps: [NavItemsService],
  multi: true,
}];

function registerBasicNavItems(navItems: NavItemsService) {
  return () => {
    navItems.addItems([
      { id: 'Languages',  order: 1, component: LanguagesComponent },
      { id: 'CurrentUser', order: 2, component: CurrentUserComponent },
    ]);
  };
}
```

Adding a custom nav item (say, an *Inbox* dropdown) is one `navItems.addItems([...])` call away.

## CurrentUserComponent + UserMenuService

`CurrentUserComponent` injects `UserMenuService` (from `@abp/ng.theme.shared`) and renders whichever entries `BASIC_THEME_USER_MENU_PROVIDERS` registered (default: *Manage profile*, *Security logs*, *Sign out*). Replace or extend the menu by adding entries via `userMenuService.addItems([...])`.

## Lazy styles

```typescript
// handlers/lazy-style.handler.ts (excerpt)
@Injectable()
export class LazyStyleHandler {
  constructor(private dom: DomInsertionService, @Inject(BASIC_THEME_STYLES) styles: string[]) {
    styles.forEach(href => this.dom.insertStyle(href));
  }
}
```

`BASIC_THEME_STYLES_PROVIDERS` provides the list of stylesheets to load at runtime — Bootstrap (`bootstrap/dist/css/bootstrap.min.css`), `@fortawesome/fontawesome-free/css/all.min.css`, and the theme's own CSS. Apps can override `BASIC_THEME_STYLES` to add or replace stylesheets.

## ValidationErrorComponent

The default error template used by `@ngx-validate/core`:

```typescript
@Component({
  selector: 'abp-validation-error',
  template: `
    <div class="invalid-feedback d-block" *ngFor="let error of errors">
      {{ error.key | abpLocalization: error.value }}
    </div>
  `,
})
export class ValidationErrorComponent { /* … */ }
```

`forRoot()` wires it as the global error template via `VALIDATION_ERROR_TEMPLATE`. `VALIDATION_TARGET_SELECTOR = '.form-group'` means errors are attached to the nearest `.form-group` ancestor, and `VALIDATION_INVALID_CLASSES = 'is-invalid'` makes Bootstrap render the red border treatment.

## Usage

```typescript
// app.module.ts
@NgModule({
  imports: [
    CoreModule.forRoot({ environment, registerLocaleFn: registerLocale() }),
    AbpOAuthModule.forRoot(),
    ThemeSharedModule.forRoot(),
    ThemeBasicModule.forRoot(),
  ],
  /* … */
})
export class AppModule {}
```

To customise the look without forking, replace single components via `ReplaceableComponentsService` — every layout/slot is registered under a stable key derived from its enum/route definition.

## Gotchas

* `static type = eLayoutType.application` is **required** on every layout component. Forgetting it makes `DynamicLayoutComponent` fall back to `EmptyLayoutComponent`.
* `ThemeBasicModule.forRoot()` registers stylesheets *lazily*. They appear after the first APP_INITIALIZER tick — for an even faster paint, add `<link rel="stylesheet" href="..."` directly to `index.html`.
* `ValidationErrorComponent` consumes `errors` shaped by `@ngx-validate/core`. Replacing it requires honouring the same `{ key, value }[]` contract.
* `NavItemsService.items$` emits in *order* — set the `order` field carefully when adding to the existing list to avoid your item jumping ahead of or behind the languages dropdown.
* The basic theme assumes Bootstrap 5 classes (`is-invalid`, `form-group`, `dropdown-menu` etc.). Custom themes must replicate the providers or override `VALIDATION_INVALID_CLASSES` to match their own class names.
