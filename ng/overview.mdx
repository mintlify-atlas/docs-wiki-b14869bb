The `npm/ng-packs/` directory is a self-contained [Nx](https://nx.dev) + [Lerna](https://lerna.js.org) monorepo that ships the Angular front-end for ABP applications. Every published `@abp/ng.*` npm package lives here, alongside the `dev-app` playground that the framework team uses while iterating on the libraries.

This page is a map. Each package gets a dedicated deep-dive elsewhere in this section — the overview just shows how the workspace is laid out, what the public packages are, and which `.NET` application modules they mirror.

## Workspace layout

```text
npm/ng-packs/
├── apps/
│   ├── dev-app/            # Angular playground used by ABP maintainers
│   └── dev-app-e2e/        # Playwright/Cypress e2e suite
├── packages/
│   ├── core/               # @abp/ng.core            — runtime kernel
│   ├── components/         # @abp/ng.components      — page/tree/chart primitives
│   ├── theme-shared/       # @abp/ng.theme.shared    — UI primitives shared by themes
│   ├── theme-basic/        # @abp/ng.theme.basic     — default Bootstrap theme
│   ├── oauth/              # @abp/ng.oauth          — angular-oauth2-oidc integration
│   ├── account/            # @abp/ng.account         — login, register, profile pages
│   ├── account-core/       # @abp/ng.account-core    — shared services for account UI
│   ├── identity/           # @abp/ng.identity        — users + roles management
│   ├── tenant-management/  # @abp/ng.tenant-management
│   ├── permission-management/  # @abp/ng.permission-management
│   ├── feature-management/ # @abp/ng.feature-management
│   ├── setting-management/ # @abp/ng.setting-management
│   ├── schematics/         # @abp/ng.schematics      — Angular CLI schematics
│   └── generators/         # @abp/nx.generators      — Nx generators
├── nx.json
├── lerna.publish.json
├── lerna.version.json
├── tsconfig.base.json
└── package.json
```

`nx.json` registers each `project.json` (one per package) so commands like `nx build core` or `nx test theme-shared` work out of the box. `lerna.publish.json` and `lerna.version.json` drive the synchronised version bump used at release time — every published package always carries the same version number (`7.4.0` at the time of writing).

| npm package | Source path | Role |

| `@abp/ng.account-core` | `packages/account-core` | `AuthWrapperService` + `TenantBoxService` |
| `@abp/ng.identity` | `packages/identity` | Users + Roles CRUD with extension hooks |

The naming differs slightly from the directory names (`packages/theme-shared` ⇒ `@abp/ng.theme.shared`); the `name` field in each `package.json` is the source of truth.

## Mapping to .NET modules

The Angular packages are 1-for-1 mirrors of the `.NET` application modules under `modules/`:

| Angular package | .NET module |
| --------------- | ----------- |
| `@abp/ng.account` | `Volo.Abp.Account` |
| `@abp/ng.identity` | `Volo.Abp.Identity` |
| `@abp/ng.tenant-management` | `Volo.Abp.TenantManagement` |
| `@abp/ng.permission-management` | `Volo.Abp.PermissionManagement` |
| `@abp/ng.feature-management` | `Volo.Abp.FeatureManagement` |
| `@abp/ng.setting-management` | `Volo.Abp.SettingManagement` |

The contracts the UI consumes (`AppService` proxies, DTOs, permission names) are auto-generated from the backend via the `proxy-add` schematic and end up under `src/app/proxy/` in the consuming app.

## Architectural layers

From the bottom up, the dependency graph looks roughly like:

```text
                 ┌────────────────────────────────────────┐
                 │  @abp/ng.identity / tenant / ...        │  feature modules
                 └─────────────────┬──────────────────────┘
                                   │
                 ┌─────────────────▼──────────────────────┐
                 │  @abp/ng.account  /  @abp/ng.components │
                 └─────────────────┬──────────────────────┘
                                   │
                 ┌─────────────────▼──────────────────────┐
                 │            @abp/ng.theme.shared         │
                 └─────────────────┬──────────────────────┘
                                   │
                 ┌─────────────────▼──────────────────────┐
                 │   @abp/ng.oauth   →   @abp/ng.core      │
                 └─────────────────────────────────────────┘
```

* `@abp/ng.core` has no peer dependency on other `@abp/ng.*` packages — it only depends on `@abp/utils`, `angular-oauth2-oidc`, `just-clone` and `just-compare`.
* `@abp/ng.theme.shared` builds on top of `core` and adds the visual primitives (Bootstrap + ng-bootstrap).
* Feature modules depend on `theme-shared` + `core` and contribute routes, menu items and permissions through the `RoutesService`/`PermissionService` exposed by core.

## CoreModule.forRoot bootstrap

Every consuming application registers the packages in `AppModule`. The dev-app shows the canonical wiring:

```typescript
// apps/dev-app/src/app/app.module.ts (excerpt)
@NgModule({
  imports: [
    BrowserModule,
    BrowserAnimationsModule,
    AppRoutingModule,
    CoreModule.forRoot({
      environment,
      registerLocaleFn: registerLocale(),
      sendNullsAsQueryParam: false,
      skipGetAppConfiguration: false,
    }),
    AbpOAuthModule.forRoot(),
    ThemeSharedModule.forRoot(),
    AccountConfigModule.forRoot(),
    IdentityConfigModule.forRoot(),
    TenantManagementConfigModule.forRoot(),
    FeatureManagementModule.forRoot(),
    SettingManagementConfigModule.forRoot(),
    ThemeLeptonXModule.forRoot(),
    SideMenuLayoutModule.forRoot(),
    AccountLayoutModule.forRoot(),
    InternetConnectionStatusComponent,
  ],
  providers: [APP_ROUTE_PROVIDER],
  declarations: [AppComponent],
  bootstrap: [AppComponent],
})
export class AppModule {}
```

The `*ConfigModule.forRoot()` wrappers are *eager* shells that register routes, permissions and contributor tokens. The *real* feature modules are loaded lazily via `forLazy()` factories — see `account-routing.module.ts` for an example.

## Build system

* **Nx** drives the task graph. `nx.json` defines `targetDefaults` so that `build` depends on `^build` (upstream packages get built first).
* **`ng-packagr`** packages each library as an Angular Package Format bundle. Each package has a sibling `ng-package.json` pointing at its `public-api.ts`.
* **Lerna** publishes — `lerna.publish.json` ignores tests/specs, runs the `publish` script, and creates GitHub releases.
* **Jest** is the test runner (`jest.preset.js` at the workspace root, plus per-package `jest.config.ts`).

## Naming conventions

| Convention | Example |
| ---------- | ------- |
| Public services end in `Service` and are `providedIn: 'root'` | `ConfigStateService`, `RestService` |
| Tokens use `SCREAMING_SNAKE_CASE` and live under `tokens/` | `CORE_OPTIONS`, `TENANT_KEY` |
| Component selectors are kebab-case with `abp-` prefix | `<abp-page>`, `<abp-tree>`, `<abp-confirmation>` |
| Replaceable components register an enum entry under `enums/components.ts` | `eAccountComponents.Login` |
| Feature modules expose `forRoot`, `forChild` *and* `forLazy` static factories | `AccountModule.forLazy()` |

These conventions are enforced by the schematics in `@abp/ng.schematics` and by the repository's `pre-commit` hook.
