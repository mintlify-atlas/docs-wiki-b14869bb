`MyCompanyName.MyProjectName.AuthServer` is a **stand-alone authorization server** that runs `/connect/authorize`, `/connect/token`, `/.well-known/openid-configuration`, and the Account module's login, registration, password reset and consent Razor Pages. It is generated when you create the solution with the *separated AuthServer* flavour (tiered MVC, tiered Blazor Server, Angular-with-separate-auth, etc.) and runs on `https://localhost:44301` in development.

The `HttpApi.Host` then validates the tokens this server mints — see [HttpApi.Host](/templates/aspnetcore/httpapi-host) for the validator side.

## Module class

```csharp
[DependsOn(
    typeof(AbpAutofacModule),
    typeof(AbpCachingStackExchangeRedisModule),
    typeof(AbpDistributedLockingModule),
    typeof(AbpAccountWebOpenIddictModule),
    typeof(AbpAccountApplicationModule),
    typeof(AbpAccountHttpApiModule),
    typeof(AbpAspNetCoreMvcUiLeptonXLiteThemeModule),
    typeof(MyProjectNameEntityFrameworkCoreModule),
    typeof(AbpAspNetCoreSerilogModule))]
public class MyProjectNameAuthServerModule : AbpModule
{
    public override void PreConfigureServices(ServiceConfigurationContext context)
    {
        PreConfigure<OpenIddictBuilder>(builder =>
        {
            builder.AddValidation(options =>
            {
                options.AddAudiences("MyProjectName");
                options.UseLocalServer();
                options.UseAspNetCore();
            });
        });
    }
    // ConfigureServices + OnApplicationInitialization
}
```

`UseLocalServer()` works because `AbpAccountWebOpenIddictModule` registers the OpenIddict server inside the same process — the validation handler can read keys directly from the in-memory OpenIddict configuration.

```csharp
Configure<AbpLocalizationOptions>(options =>
```

Setting `ApplicationName = "AuthServer"` tags every audit log entry produced by this host so you can distinguish login events from API calls in `AbpAuditLogs`.

### Background jobs disabled

```csharp
Configure<AbpBackgroundJobOptions>(options =>
{
    options.IsJobExecutionEnabled = false;
});
```

This host should not execute background jobs — that responsibility belongs to a dedicated worker (or to the API host).

### Data protection + distributed locking

Same pattern as `HttpApi.Host`: in production keys persist to Redis, and a `RedisDistributedSynchronizationProvider` powers `IDistributedLockProvider`.

### CORS

```csharp
context.Services.AddCors(options =>
{
    options.AddDefaultPolicy(builder =>
    {
        builder
            .WithOrigins(configuration["App:CorsOrigins"]?
                .Split(",", StringSplitOptions.RemoveEmptyEntries)
                .Select(o => o.RemovePostFix("/")).ToArray() ?? Array.Empty<string>())
            .WithAbpExposedHeaders()
            .SetIsOriginAllowedToAllowWildcardSubdomains()
            .AllowAnyHeader()
            .AllowAnyMethod()
            .AllowCredentials();
    });
});
```

`AllowCredentials()` is mandatory — the silent-renew iframe in SPA clients needs to send the authentication cookie cross-origin.

### Virtual file system

In development, embedded resources are replaced by physical paths inside the `framework/` and `modules/` source trees so you can edit Razor Pages and re-launch without `dotnet pack`-ing intermediate packages.

```json
{
  "App": {

    "ClientUrl": "http://localhost:4200",
    "CorsOrigins": "https://*.MyProjectName.com,http://localhost:4200,https://localhost:44307,https://localhost:44300",
    "RedirectAllowedUrls": "http://localhost:4200,https://localhost:44302,https://localhost:44307,https://localhost:44309"
  },
  "ConnectionStrings": {
    "Default": "Server=(LocalDb)\\MSSQLLocalDB;Database=MyProjectName;Trusted_Connection=True;TrustServerCertificate=True"
  },
  "Redis": { "Configuration": "127.0.0.1" },
  "StringEncryption": {
    "DefaultPassPhrase": "gsKnGZ041HLL4IM8"
  }
}
```

The `RedirectAllowedUrls` list explicitly enumerates every URL that may receive the post-login redirect — `44302` (Web), `44307` (Blazor WASM), `44309` (Blazor Server Tiered), plus the Angular SPA at `4200`. Any client URL missing from this list is rejected with `OpenIddictException: invalid redirect_uri`.

## OpenIddict client seeding

Client records are seeded by `OpenIddictDataSeedContributor` in `Domain` using the configuration in `DbMigrator/appsettings.json`:

```json
"OpenIddict": {
  "Applications": {
    "MyProjectName_Web":               { "ClientId": "MyProjectName_Web",               "ClientSecret": "1q2w3e*", "RootUrl": "https://localhost:44302" },
    "MyProjectName_Blazor":            { "ClientId": "MyProjectName_Blazor",                                      "RootUrl": "https://localhost:44307" },
    "MyProjectName_App":               { "ClientId": "MyProjectName_App",                                         "RootUrl": "http://localhost:4200"  },
    "MyProjectName_BlazorServerTiered":{ "ClientId": "MyProjectName_BlazorServerTiered", "ClientSecret": "1q2w3e*", "RootUrl": "https://localhost:44309" },
    "MyProjectName_Swagger":           { "ClientId": "MyProjectName_Swagger",                                      "RootUrl": "https://localhost:44305" }
  }
}
```

A confidential client (Hybrid flow) has a `ClientSecret`; a public client (PKCE) does not. The contributor uses the existence of the secret to pick the correct grant types.

| Persistent encryption certificate     | `OpenIddictBuilder.AddServer(b => b.AddEncryptionCertificate(...))` |

## Gotchas

- **Development uses ephemeral keys.** `AbpAccountWebOpenIddictModule` registers ephemeral signing and encryption keys when no certificates are configured — restart the host and existing tokens become invalid. Provision real X.509 certificates for staging/production via the `OpenIddictBuilder.AddServer` extension.
- **Redis is required across replicas.** Without a shared data-protection keyring, replica A signs the antiforgery token but replica B cannot validate it, causing intermittent login failures.
- **`AbpBackgroundJobOptions.IsJobExecutionEnabled = false` is intentional.** This host has the application contracts assembly loaded transitively but should not pick up scheduled jobs. If you turn it back on you risk running expensive jobs on what should be a hot login path.
- **Client redirect URIs are *case-sensitive*.** `https://localhost:44307/` and `https://localhost:44307` are treated differently by OpenIddict. Make sure the URL in the seed file ends with `/` (the contributor calls `.EnsureEndsWith('/')` on `RootUrl`).
- **No HTTP API surface here.** Don't try to add `MyProjectNameApplicationModule` as a dependency — you would end up authorizing API calls inside a process that is also the issuer, which is the exact scenario `HttpApi.HostWithIds` covers. Choose one host model.
- **`CorsOrigins` must include every Web/Blazor/SPA self-URL.** Missing the Angular dev URL produces a CORS failure during silent-renew that surfaces in the browser console as `Refused to display...` without any server log entry.
- **`MultiTenancyConsts.IsEnabled = false` removes the tenant switch from the login UI** but does **not** remove the tenant cookie middleware from the pipeline. Both are gated by the same boolean so behaviour stays consistent.
