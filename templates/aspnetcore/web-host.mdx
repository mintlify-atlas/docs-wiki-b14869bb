`MyCompanyName.MyProjectName.Web.Host` is the **UI tier** of the tiered MVC template. It is generated when you pass `--tiered` to `abp new ... -u mvc`. It hosts the same Razor Pages and menu contributors as the non-tiered [Web](/templates/aspnetcore/web) project, but talks to the application services over HTTP through `HttpApi.Client` rather than calling them in-process.

The accompanying `HttpApi.Host` and `AuthServer` projects must be running for this host to operate; the architecture is:

```
Browser  ⇄  Web.Host (this project, port 44302)
                    ⇄ AuthServer (port 44301) via OpenID Connect (Authorization Code + PKCE)
                    ⇄ HttpApi.Host (port 44300) via HTTP, access token forwarded
```

## Module class

```csharp
[DependsOn(
    typeof(MyProjectNameHttpApiClientModule),
    typeof(MyProjectNameHttpApiModule),
    typeof(AbpAspNetCoreAuthenticationOpenIdConnectModule),
    typeof(AbpAspNetCoreMvcClientModule),
    typeof(AbpHttpClientWebModule),
    typeof(AbpAspNetCoreMvcUiLeptonXLiteThemeModule),
    typeof(AbpAutofacModule),
    typeof(AbpCachingStackExchangeRedisModule),
    typeof(AbpDistributedLockingModule),
    typeof(AbpSettingManagementWebModule),
    typeof(AbpHttpClientIdentityModelWebModule),
    typeof(AbpIdentityWebModule),
    typeof(AbpTenantManagementWebModule),
    typeof(AbpAspNetCoreSerilogModule),
    typeof(AbpSwashbuckleModule))]
public class MyProjectNameWebModule : AbpModule
{
    public override void PreConfigureServices(ServiceConfigurationContext context)
    {
        context.Services.PreConfigure<AbpMvcDataAnnotationsLocalizationOptions>(options =>
        {
            options.AddAssemblyResource(
                typeof(MyProjectNameResource),
                typeof(MyProjectNameDomainSharedModule).Assembly,
                typeof(MyProjectNameApplicationContractsModule).Assembly,
                typeof(MyProjectNameWebModule).Assembly);
        });
    }
    // ConfigureServices, OnApplicationInitialization
}
```

Notice the smaller assembly list passed to `AddAssemblyResource`: there is **no Domain or Application reference** because this host never sees those assemblies. Validation messages for DTOs still resolve because `MyProjectNameApplicationContractsModule` contains the localization markers.

### Authentication

```csharp
context.Services.AddAuthentication(options =>
    {
        options.DefaultScheme = "Cookies";
        options.DefaultChallengeScheme = "oidc";
    })
    .AddCookie("Cookies", options =>
    {
        options.ExpireTimeSpan = TimeSpan.FromDays(365);
        options.CheckTokenExpiration();
    })
    .AddAbpOpenIdConnect("oidc", options =>
    {
        options.Authority = configuration["AuthServer:Authority"];
        options.RequireHttpsMetadata = Convert.ToBoolean(configuration["AuthServer:RequireHttpsMetadata"]);
        options.ResponseType = OpenIdConnectResponseType.CodeIdToken;
        options.ClientId = configuration["AuthServer:ClientId"];
        options.ClientSecret = configuration["AuthServer:ClientSecret"];
        options.UsePkce = true;
        options.SaveTokens = true;
        options.GetClaimsFromUserInfoEndpoint = true;
        options.Scope.Add("roles");
        options.Scope.Add("email");
        options.Scope.Add("phone");
        options.Scope.Add("MyProjectName");
    });
```

The cookie is the **session container** (long-lived, 365 days), the OIDC handler is the **login mechanism**. `CheckTokenExpiration` is an ABP extension that refreshes the cookie if the underlying access token has expired but the refresh token is still valid.

`SaveTokens = true` is the critical line — without it the access token cannot be re-read later to forward to the API tier.

`GetClaimsFromUserInfoEndpoint = true` fetches `email`, `phone`, etc. after a successful login so the cookie contains the full user profile.

### Data protection + distributed locking

Same Redis-backed pattern as the other hosts. Mandatory whenever you scale this Web.Host horizontally because the cookie's protection keys must be shared.

There is no `UseAbpOpenIddictValidation()` here — this host is a **client**, not a validator. Bearer tokens are not accepted; cookies are.

## appsettings.json

```json
{
  "App": {
    "SelfUrl": "https://localhost:44302"
  },
  "RemoteServices": {
    "Default": { "BaseUrl": "https://localhost:44300/" }
  },
  "Redis": { "Configuration": "127.0.0.1" },
  "AuthServer": {
    "Authority": "https://localhost:44301",
    "RequireHttpsMetadata": "true",
    "ClientId": "MyProjectName_Web",
    "ClientSecret": "1q2w3e*"
  },
  "StringEncryption": {
    "DefaultPassPhrase": "gsKnGZ041HLL4IM8"
  }
}
```

- `RemoteServices.Default.BaseUrl` — the URL of `HttpApi.Host`. Every HttpClient proxy from `MyProjectNameHttpApiClientModule` targets this base.
- `AuthServer.Authority` — the URL of the standalone `AuthServer`.
- `AuthServer.ClientId` / `ClientSecret` — confidential client credentials. The seed file in `DbMigrator/appsettings.json` registers `MyProjectName_Web` with `ClientSecret: "1q2w3e*"`.

## Gotchas

- **Cookies require Redis-backed Data Protection to scale.** Without a shared keyring, replica A signs the cookie and replica B rejects it.
- **`SaveTokens = true` puts the access token in the cookie.** Cookies expand quickly — keep request size limits high on any reverse proxy in front of the host. Without `SaveTokens` the HttpClient proxies cannot forward the access token to the API host.
- **`ClientSecret` is confidential.** Use User Secrets locally and a secret store (Azure Key Vault, AWS Parameter Store) in production. Committing it to `appsettings.json` works for the template demo but is unsafe.
- **The OIDC handler does NOT honour `AppUrlOptions["Angular"]`.** That URL is only used by the AuthServer when sending password-reset emails to Angular SPA users. If your tiered MVC users live on a different DNS, set `App:SelfUrl` accordingly *and* add the URL to `RedirectAllowedUrls` in `AuthServer/appsettings.json`.
- **There is no `EntityFrameworkCore` reference.** Trying to inject `IRepository<Book>` here fails at startup. All data access must go through the application service interfaces resolved as HTTP proxies.
- **Tenant cookie domain.** When the AuthServer and Web.Host are on different subdomains (e.g. `auth.example.com` and `app.example.com`) the tenant cookie has to be domain-scoped — configure `AbpMultiTenancyCookieOptions.CookieDomain = ".example.com"` to keep tenant selection across the OIDC round trip.
- **No `Volo.Abp.Account.Web` reference here.** Trying to load `/Account/Login` will 404 because the login pages live on the AuthServer. The OIDC handler redirects users there automatically.
