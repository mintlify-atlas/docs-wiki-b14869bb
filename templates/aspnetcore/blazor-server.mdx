`MyCompanyName.MyProjectName.Blazor.Server` is the **Blazor Server** host generated when you run `abp new ... -u blazor-server` (without `--tiered`). Components execute on the server; the browser only receives DOM diffs over a SignalR circuit. The same process serves the HTTP API, OpenIddict authentication endpoints, and the Razor Pages for the Account module.

Compared to Blazor WebAssembly, this model is closer to traditional ASP.NET — components have direct access to `IApplicationService`, `IRepository`, and the EF Core `DbContext`, all running inside the host's DI container.

## Module class

```csharp
[DependsOn(
    typeof(MyProjectNameApplicationModule),
    typeof(MyProjectNameEntityFrameworkCoreModule),
    typeof(MyProjectNameHttpApiModule),
    typeof(AbpAutofacModule),
    typeof(AbpSwashbuckleModule),
    typeof(AbpAspNetCoreSerilogModule),
    typeof(AbpAccountWebOpenIddictModule),
    typeof(AbpAspNetCoreComponentsServerLeptonXLiteThemeModule),
    typeof(AbpAspNetCoreMvcUiLeptonXLiteThemeModule),
    typeof(AbpIdentityBlazorServerModule),
    typeof(AbpTenantManagementBlazorServerModule),
    typeof(AbpSettingManagementBlazorServerModule))]
public class MyProjectNameBlazorModule : AbpModule
{
    public override void PreConfigureServices(ServiceConfigurationContext context)
    {
        context.Services.PreConfigure<AbpMvcDataAnnotationsLocalizationOptions>(options =>
        {
            options.AddAssemblyResource(
                typeof(MyProjectNameResource),
                typeof(MyProjectNameDomainModule).Assembly,
                typeof(MyProjectNameDomainSharedModule).Assembly,
                typeof(MyProjectNameApplicationModule).Assembly,
                typeof(MyProjectNameApplicationContractsModule).Assembly,
                typeof(MyProjectNameBlazorModule).Assembly);
        });

        PreConfigure<OpenIddictBuilder>(builder =>
        {
            builder.AddValidation(options =>
            {
                options.AddAudiences("MyProjectName");
                options.UseLocalServer();
                options.UseAspNetCore();
            });
        });
    }
    // ConfigureServices + OnApplicationInitialization
}
```

Highlights worth calling out:

- **Two themes** are referenced: the MVC theme (`LeptonXLite`) for Account/Razor pages and the Blazor theme (`Server.LeptonXLiteTheme`) for components. Both must be registered or the login page renders without styling.
- **Application + EntityFrameworkCore are referenced directly.** Components can resolve `IRepository<T>` and `IBookAppService` from DI without HTTP round-trips.

### Bundles

```csharp
options.StyleBundles.Configure(
    LeptonXLiteThemeBundles.Styles.Global,
    bundle => bundle.AddFiles("/global-styles.css"));

options.StyleBundles.Configure(
    BlazorLeptonXLiteThemeBundles.Styles.Global,
    bundle =>
    {
        bundle.AddFiles("/blazor-global-styles.css");
        bundle.AddFiles("/MyCompanyName.MyProjectName.Blazor.Server.styles.css");
    });
```

The second bundle adds Blazor's CSS isolation output (`*.styles.css`) to the global bundle. Remove that line if you choose not to use CSS isolation.

### Authentication

Same `ForwardIdentityAuthenticationForBearer(OpenIddictValidationAspNetCoreDefaults.AuthenticationScheme)` call as `HttpApi.HostWithIds` — the host's API surface is bearer-authenticated, the Blazor components themselves rely on the cookie produced by Razor Pages login.

### Virtual file system

In development the module pins every depended module to its source path under `framework/` and `modules/`. This includes Blazor-specific modules like `AbpIdentityBlazorServerModule` so editing a `.razor` component in the identity module triggers hot reload.

## Program.cs

```csharp
public class Program
{
    public async static Task<int> Main(string[] args)
    {
        Log.Logger = /* Serilog */;
        try
        {
            var builder = WebApplication.CreateBuilder(args);
            builder.Host.AddAppSettingsSecretsJson().UseAutofac().UseSerilog();
            await builder.AddApplicationAsync<MyProjectNameBlazorModule>();
            var app = builder.Build();
            await app.InitializeApplicationAsync();
            await app.RunAsync();
            return 0;
        }
        catch (Exception ex)
        {
            if (ex is HostAbortedException) throw;
            Log.Fatal(ex, "Host terminated unexpectedly!");
            return 1;
        }
        finally { Log.CloseAndFlush(); }
    }
}
```

Same shape as the other Web hosts.

## Gotchas

- **Blazor Server circuits are scoped.** A single SignalR connection equals one DI scope that lives for the duration of the connection. Singleton services injected into many components will survive every reconnect; scoped services do *not* share state between two open tabs. Designing for this is more nuanced than for a stateless HTTP request.
- **`IRepository<T>`/`DbContext` are scoped to the circuit.** Holding a reference across an `await` boundary can leak the underlying `DbContext` for hours. Always resolve through `[Inject]` properties, not constructor fields, and use `using var scope = ScopeFactory.CreateScope()` for long-running background work.
- **The Account module's Login page uses MVC, not Blazor.** The host loads two themes precisely because the login flow renders as a Razor Page. Removing `AbpAspNetCoreMvcUiLeptonXLiteThemeModule` produces an unstyled login screen.
- **`MultiTenancyConsts.IsEnabled = false` removes the tenant cookie middleware.** The Razor Pages tenant switch disappears from the UI but the underlying `AbpMultiTenancyOptions.IsEnabled` is also `false`, so global queries are no longer tenant-filtered — exactly the intended behaviour.
- **Hot reload requires `dotnet watch run`.** `dotnet run` will not pick up `.razor` changes; the embedded resource paths to `framework/` and `modules/` only help with bundled JSON/cshtml files.
- **No `RemoteServices` section is needed.** The host calls `IApplicationService` interfaces in-process; the HTTP proxies from `HttpApi.Client` are not referenced. Adding the package would cause every call to do a self-loopback HTTP request.
- **The Blazor circuit's authentication state changes when the cookie expires.** Use the cascading `AuthenticationStateProvider` (`Task<AuthenticationState>`) to react; the static `ICurrentUser` will *also* update once the next service call resolves, but UI components must subscribe to `AuthenticationStateChanged` to re-render.
