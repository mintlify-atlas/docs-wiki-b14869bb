`MyCompanyName.MyProjectName.Domain.Shared` is the lowest-level project in the application template. It is referenced — directly or transitively — by every other project in the solution because it holds the **constants, enums, localization resources and shared types** that must be visible from both the host and the client (Blazor WebAssembly, Xamarin, NuGet consumer) sides of the system.

The project ships with the [`abp new` template](https://docs.abp.io/en/abp/latest/Startup-Templates/Application) under `templates/app/aspnet-core/src/MyCompanyName.MyProjectName.Domain.Shared/` and is generated for **every** UI/database flavour (MVC, Blazor, Angular, MAUI; EF Core or MongoDB).

## When to put code here

Use `Domain.Shared` if the type satisfies **all** of these rules:

- It has no dependency on EF Core, AutoMapper, or any UI-side library.
- It must compile against `netstandard2.0`/`netstandard2.1` so it can be referenced from Blazor WebAssembly clients.
- It is safe to ship to *untrusted* consumers (it contains no business logic, repository contracts, or secrets).

Typical contents are constants, enums, error-code strings, multi-tenancy flags, localization resource markers, and the `ModuleExtensionConfigurator` that pre-configures ABP's object-extension system.

The 24 JSON files are the **embedded localization resources** for the application. They are added as `<EmbeddedResource Include="Localization\MyProjectName\*.json" />` in the csproj so the templates can ship across NuGet boundaries without leaking loose files into consumer build output.

## Module class

`MyProjectNameDomainSharedModule` depends on the eight `*.Domain.Shared` modules above and configures three sub-systems:

```csharp
[DependsOn(
    typeof(AbpAuditLoggingDomainSharedModule),
    typeof(AbpBackgroundJobsDomainSharedModule),
    typeof(AbpFeatureManagementDomainSharedModule),
    typeof(AbpIdentityDomainSharedModule),
    typeof(AbpOpenIddictDomainSharedModule),
    typeof(AbpPermissionManagementDomainSharedModule),
    typeof(AbpSettingManagementDomainSharedModule),
    typeof(AbpTenantManagementDomainSharedModule))]
public class MyProjectNameDomainSharedModule : AbpModule
{
    public override void PreConfigureServices(ServiceConfigurationContext context)
    {
        MyProjectNameGlobalFeatureConfigurator.Configure();
        MyProjectNameModuleExtensionConfigurator.Configure();
    }
}
```

### Virtual file system

`ConfigureServices` registers the embedded resources so any consumer can read the JSON files through `IVirtualFileProvider`:

```csharp
Configure<AbpVirtualFileSystemOptions>(options =>
{
    options.FileSets.AddEmbedded<MyProjectNameDomainSharedModule>();
});
```

### Localization

A single resource class — `MyProjectNameResource` — is created with English as the default culture and is wired to read keys from `/Localization/MyProjectName`. It inherits from `AbpValidationResource` so model validation messages can be localized using the same dictionary.

```csharp
Configure<AbpLocalizationOptions>(options =>
{
    options.Resources
        .Add<MyProjectNameResource>("en")
        .AddBaseTypes(typeof(AbpValidationResource))
        .AddVirtualJson("/Localization/MyProjectName");

    options.DefaultResourceType = typeof(MyProjectNameResource);
});
```

### Exception localization

```csharp
Configure<AbpExceptionLocalizationOptions>(options =>
{
    options.MapCodeNamespace("MyProjectName", typeof(MyProjectNameResource));
});
```

The `MapCodeNamespace` call binds error codes prefixed `"MyProjectName"` (declared in `MyProjectNameDomainErrorCodes`) to the localization resource so `BusinessException("MyProjectName:00001")` is automatically translated.

## Key types

### MyProjectNameResource

An empty class used purely as a localization marker. Pages reference it through `[LocalizationResource(typeof(MyProjectNameResource))]` or `IStringLocalizer<MyProjectNameResource>`.

### MultiTenancyConsts

```csharp
public static class MultiTenancyConsts
{
    public const bool IsEnabled = true;
}
```

This **single boolean** is read by `MyProjectNameDomainModule`, `MyProjectNameHttpApiHostModule`, the Web/Blazor host modules, and the menu contributors. Setting it to `false` disables multi-tenancy everywhere in one place — no other files need editing.

### MyProjectNameDomainErrorCodes

Empty container for business-exception error codes:

```csharp
public static class MyProjectNameDomainErrorCodes
{
    /* You can add your business exception error codes here, as constants */
}
```

Codes are conventionally `"MyProjectName:00001"` strings so the `MapCodeNamespace` registration above translates them.

### MyProjectNameGlobalFeatureConfigurator

Static class with a `OneTimeRunner` guard that lets you enable or disable [global features](https://docs.abp.io/en/abp/latest/Global-Features) of the depended modules. The runner pattern guarantees the configuration is applied at most once per process, even if multiple test fixtures instantiate the host.

### MyProjectNameModuleExtensionConfigurator

Two extension points — `ConfigureExistingProperties()` and `ConfigureExtraProperties()` — that wire ABP's [Module Entity Extension](https://docs.abp.io/en/abp/latest/Module-Entity-Extensions) system. The template ships them empty so you can:

- Increase `AbpUserConsts.MaxNameLength` for the Identity user, or
- Register a new property on `IdentityUser` (`SocialSecurityNumber`) with validation attributes via `ObjectExtensionManager.Instance.Modules().ConfigureIdentity(...)`.

Both calls happen inside `PreConfigureServices` so dependent modules see the changes when they register entities and DTOs.

## Customization points

| Need                                              | File / API                                                                              |
| ------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Add a UI string                                   | New key in `Localization/MyProjectName/en.json`                                         |
| Disable multi-tenancy globally                    | `MultiTenancyConsts.IsEnabled = false`                                                  |
| Add a business error code                         | Constant in `MyProjectNameDomainErrorCodes`, key in `en.json` under `Volo.Abp.Validation:` or your namespace |
| Add an extension property to a module entity      | `MyProjectNameModuleExtensionConfigurator.ConfigureExtraProperties()`                  |
| Enable/disable a Global Feature                   | `MyProjectNameGlobalFeatureConfigurator.Configure()`                                    |
| Add a new language to the dropdown                | Add a `<culture>.json` file and add a `LanguageInfo` entry in `MyProjectNameDomainModule` |

## Gotchas

- **Do not add EF Core, AutoMapper or HttpClient code here.** The project multi-targets `netstandard2.0` so any reference that pulls in `net7.0`-only assemblies (like `Microsoft.EntityFrameworkCore.SqlServer`) will break the Blazor WebAssembly build downstream.
- **Localization JSON files must be embedded.** If you add a file outside `Localization/MyProjectName/`, also update the `<EmbeddedResource Include="..." />` glob — otherwise `AddVirtualJson("/Localization/MyProjectName")` will silently miss it at runtime.
- **`OneTimeRunner` is required** for the configurators. If you replace it with a plain method call your code may run twice when [`AbpApplicationFactory`](https://docs.abp.io/en/abp/latest/Application-Startup) is invoked from tests, throwing duplicate-key exceptions out of `ObjectExtensionManager`.
- **`MapCodeNamespace` is namespace-sensitive.** The string `"MyProjectName"` must match the prefix used in your error-code constants exactly; otherwise translation silently falls through to the raw code.
- The `Nullable` flag is `enable`. New code in this project must use nullable annotations or it will produce warnings-as-errors when consumers compile with `TreatWarningsAsErrors`.
