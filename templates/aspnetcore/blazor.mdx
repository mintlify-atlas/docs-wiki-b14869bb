`MyCompanyName.MyProjectName.Blazor` is the **Blazor WebAssembly** UI generated when you create the solution with `abp new ... -u blazor`. It runs entirely in the browser as a downloaded SPA, authenticates the user against a separately-hosted [AuthServer](/templates/aspnetcore/authserver) (or `HttpApi.HostWithIds`), and calls application services through `MyProjectNameHttpApiClientModule`.

This is **WebAssembly**, not Blazor Server — the runtime lives in the browser, the UI does not maintain a persistent SignalR connection, and every service must be safe to instantiate inside the WASM sandbox.

## Module class

```csharp
[DependsOn(
    typeof(AbpAutofacWebAssemblyModule),
    typeof(MyProjectNameHttpApiClientModule),
    typeof(AbpAspNetCoreComponentsWebAssemblyLeptonXLiteThemeModule),
    typeof(AbpIdentityBlazorWebAssemblyModule),
    typeof(AbpTenantManagementBlazorWebAssemblyModule),
    typeof(AbpSettingManagementBlazorWebAssemblyModule))]
public class MyProjectNameBlazorModule : AbpModule
{
    public override void ConfigureServices(ServiceConfigurationContext context)
    {
        var environment = context.Services.GetSingletonInstance<IWebAssemblyHostEnvironment>();
        var builder = context.Services.GetSingletonInstance<WebAssemblyHostBuilder>();

        ConfigureAuthentication(builder);
        ConfigureHttpClient(context, environment);
        ConfigureBlazorise(context);
        ConfigureRouter(context);
        ConfigureUI(builder);
        ConfigureMenu(context);
        ConfigureAutoMapper(context);
    }
    // ...
}
```

### Authentication (OIDC silent renew)

```csharp
private static void ConfigureAuthentication(WebAssemblyHostBuilder builder)
{
    builder.Services.AddOidcAuthentication(options =>
    {
        builder.Configuration.Bind("AuthServer", options.ProviderOptions);
        options.UserOptions.NameClaim = OpenIddictConstants.Claims.Name;
        options.UserOptions.RoleClaim = OpenIddictConstants.Claims.Role;

        options.ProviderOptions.DefaultScopes.Add("MyProjectName");
        options.ProviderOptions.DefaultScopes.Add("roles");
        options.ProviderOptions.DefaultScopes.Add("email");
        options.ProviderOptions.DefaultScopes.Add("phone");
    });
}
```

The `Microsoft.AspNetCore.Components.WebAssembly.Authentication` package handles the redirect/silent-renew flow. The `AuthServer:Authority` URL in `wwwroot/appsettings.json` points at the OpenID provider; the `DefaultScopes` list mirrors the scopes the AuthServer's `OpenIddictDataSeedContributor` granted to the `MyProjectName_Blazor` client.

The `NameClaim` / `RoleClaim` overrides are mandatory because OpenIddict uses different default claim names than the standard `ClaimTypes.Name` / `ClaimTypes.Role` Blazor expects.

### Router, HttpClient, UI

```csharp
Configure<AbpRouterOptions>(options =>
{
    options.AppAssembly = typeof(MyProjectNameBlazorModule).Assembly;
});

context.Services.AddTransient(sp => new HttpClient
{
    BaseAddress = new Uri(environment.BaseAddress)
});

builder.RootComponents.Add<App>("#ApplicationContainer");
```

- `AppAssembly` lets ABP's routing module discover `[Route]`-decorated components in this assembly.
- The transient `HttpClient` uses the host's base address so static asset requests stay relative; API calls override the URL through `MyProjectNameHttpApiClientModule.RemoteServiceName`.

## Program.cs

```csharp
public class Program
{
    public async static Task Main(string[] args)
    {
        var builder = WebAssemblyHostBuilder.CreateDefault(args);

        var application = await builder.AddApplicationAsync<MyProjectNameBlazorModule>(options =>
        {
            options.UseAutofac();
        });

        var host = builder.Build();
        await application.InitializeApplicationAsync(host.Services);
        await host.RunAsync();
    }
}
```

`WebAssemblyHostBuilder.CreateDefault` reads `wwwroot/appsettings.json` and `wwwroot/appsettings.{Environment}.json` automatically. `options.UseAutofac()` swaps the default `ServiceProvider` for an Autofac container so property injection works inside `AbpComponentBase`.

## wwwroot/appsettings.json

A typical configuration:

```json
{
  "RemoteServices": {
    "Default": { "BaseUrl": "https://localhost:44305/" }
  },
  "AuthServer": {
    "Authority": "https://localhost:44305",
    "ClientId": "MyProjectName_Blazor",
    "ResponseType": "code"
  }
}
```

Both URLs commonly point at `HttpApi.HostWithIds` (port `44305`) because the WASM template's default deployment is the *non-tiered* flavour. If you run the tiered solution, point `RemoteServices.Default.BaseUrl` at `HttpApi.Host` (44300) and `AuthServer.Authority` at `AuthServer` (44301).

## Gotchas

- **The WASM publish step rejects net7.0-only references.** Adding `Microsoft.EntityFrameworkCore` or any server-side ABP module (`Application`, `Domain`, `EntityFrameworkCore`) will break `dotnet publish` with `NETSDK1080`. Stay on the `*.HttpApi.Client` boundary.
- **`AddOidcAuthentication` does NOT support cookies.** Blazor WASM is a static SPA — tokens live in browser storage. Logout requires explicit redirect to the AuthServer's `/connect/endsession` (ABP does this automatically through the menu contributor's Logout item).
- **Silent renew relies on an iframe** loaded from the AuthServer. Same-origin policy blocks the renew if your CORS policy on the AuthServer is too restrictive — make sure the Blazor URL is in `App:RedirectAllowedUrls` and the `MyProjectName_Blazor` client has the matching `RootUrl` in the seed file.
- **`BlazorWebAssemblyLoadAllGlobalizationData` doubles the payload size.** It is on by default so `IStringLocalizer` can format dates/numbers in any culture. Set it to `false` if you only target English to shave ~3 MB off the download.
- **PWA service worker caches the entire app.** A new deployment requires the user to close every browser tab serving the previous version or they will keep loading the cached JS. The published `service-worker.published.js` already implements a version check; do not delete it.
- **`NameClaim`/`RoleClaim` overrides are mandatory.** Without them `@attribute [Authorize(Roles = "admin")]` returns false because OpenIddict puts roles into `role` claims (lowercase), not `ClaimTypes.Role`.
- **The `Configuration.Bind("AuthServer", options.ProviderOptions)` call ignores unknown keys silently.** Typos in `wwwroot/appsettings.json` (e.g. `Authoryti` instead of `Authority`) lead to immediate redirect-to-login loops with no error displayed.
