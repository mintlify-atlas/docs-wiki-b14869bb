`MyCompanyName.MyProjectName.Blazor.Server.Tiered` is the **tiered** flavour of the Blazor Server host, generated when you run `abp new ... -u blazor-server --tiered`. Like [Web.Host](/templates/aspnetcore/web-host), it does **not** reference the Application or EntityFrameworkCore projects — application services are reached over HTTP through `HttpApi.Client`, and authentication is delegated to a separate [AuthServer](/templates/aspnetcore/authserver).

The architecture is:

```
Browser  ⇄  Blazor.Server.Tiered (this project, port 44309)  [SignalR circuit + server-rendered UI]
                    ⇄ AuthServer (port 44301)  via OpenID Connect (Hybrid + PKCE)
                    ⇄ HttpApi.Host (port 44300) via HTTP, access token forwarded
```

## Module class

```csharp
[DependsOn(
    typeof(MyProjectNameHttpApiClientModule),
    typeof(AbpCachingStackExchangeRedisModule),
    typeof(AbpDistributedLockingModule),
    typeof(AbpAspNetCoreMvcClientModule),
    typeof(AbpAspNetCoreAuthenticationOpenIdConnectModule),
    typeof(AbpHttpClientIdentityModelWebModule),
    typeof(AbpAspNetCoreComponentsServerLeptonXLiteThemeModule),
    typeof(AbpAspNetCoreMvcUiLeptonXLiteThemeModule),
    typeof(AbpAutofacModule),
    typeof(AbpSwashbuckleModule),
    typeof(AbpAspNetCoreSerilogModule),
    typeof(AbpIdentityBlazorServerModule),
    typeof(AbpTenantManagementBlazorServerModule),
    typeof(AbpSettingManagementBlazorServerModule))]
public class MyProjectNameBlazorModule : AbpModule
{
    public override void PreConfigureServices(ServiceConfigurationContext context)
    {
        context.Services.PreConfigure<AbpMvcDataAnnotationsLocalizationOptions>(options =>
        {
            options.AddAssemblyResource(
                typeof(MyProjectNameResource),
                typeof(MyProjectNameDomainSharedModule).Assembly,
                typeof(MyProjectNameApplicationContractsModule).Assembly,
                typeof(MyProjectNameBlazorModule).Assembly);
        });
    }
}
```

The `AddAssemblyResource` list omits `Domain` and `Application` because those assemblies are not referenced — only `Domain.Shared` and `Application.Contracts` flow through `HttpApi.Client`.

### Authentication

```csharp
context.Services.AddAuthentication(options =>
    {
        options.DefaultScheme = "Cookies";
        options.DefaultChallengeScheme = "oidc";
    })
    .AddCookie("Cookies", options =>
    {
        options.ExpireTimeSpan = TimeSpan.FromDays(365);
        options.IntrospectAccessToken();
    })
    .AddAbpOpenIdConnect("oidc", options =>
    {
        options.Authority = configuration["AuthServer:Authority"];
        options.RequireHttpsMetadata = Convert.ToBoolean(configuration["AuthServer:RequireHttpsMetadata"]);
        options.ResponseType = OpenIdConnectResponseType.CodeIdToken;
        options.ClientId = configuration["AuthServer:ClientId"];
        options.ClientSecret = configuration["AuthServer:ClientSecret"];
        options.SaveTokens = true;
        options.GetClaimsFromUserInfoEndpoint = true;
        options.Scope.Add("roles");
        options.Scope.Add("email");
        options.Scope.Add("phone");
        options.Scope.Add("MyProjectName");
    });
```

Three differences from the WASM flavour:

- **Hybrid flow** (`CodeIdToken`) — a confidential client with a secret.
- **`IntrospectAccessToken()`** on the cookie — periodically validates the access token against the AuthServer; revoked tokens kick the user out the next request.
- **`SaveTokens = true`** — the access token is persisted inside the cookie so `Volo.Abp.Http.Client.IdentityModel.Web` can forward it to the HttpApi.Host on every API call.

## Gotchas

- **`IntrospectAccessToken()` requires a network call every request.** Disable it (`CheckTokenExpiration()` instead) in latency-sensitive scenarios; you trade real-time revocation for response speed.
- **Cookies carry the access token thanks to `SaveTokens = true`.** That makes the cookie large — ensure your reverse proxy allows headers >8 KB and consider a Redis-backed ticket store (`ITicketStore`) for very large claim sets.
- **`ClientSecret` is committed to `appsettings.json` by default.** Move it to User Secrets locally and to a vault in production. The seed contributor reads from `DbMigrator/appsettings.json`, so both files should be kept in sync.
- **No `Application`/`EntityFrameworkCore` references means no `IRepository<T>` here.** Components inject application service interfaces from `Application.Contracts`; the runtime substitutes HTTP proxies via `MyProjectNameHttpApiClientModule`.
- **SignalR circuit + OIDC handshake.** The OIDC login redirects break the SignalR connection; the framework reconnects automatically once the user lands back on the host. Long-running components must handle `OnAfterRenderAsync` re-runs without duplicating side effects.
- **`Redis:Configuration` is mandatory.** Without Redis the distributed cache falls back to in-memory and `IDistributedLockProvider` cannot be resolved at startup — `ConfigureDistributedLocking` throws.
- **The OIDC callback path is `/signin-oidc` by default.** Make sure this is allowed by the AuthServer's `RedirectAllowedUrls` — the seed configures `https://localhost:44309/signin-oidc` implicitly via the `RootUrl + "signin-oidc"` convention.
- **Account pages do NOT exist here.** Trying to navigate to `/Account/Login` returns 404; the browser is redirected to the AuthServer instead. The Login link in the menu contributor uses the OIDC challenge URL, not a direct route.
