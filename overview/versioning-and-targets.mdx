ABP's 152 framework packages plus 19 application modules are versioned and targeted through a tiny set of MSBuild props files at the repository root. Every csproj imports `common.props` for `Version`, license and SourceLink, every csproj that ships async code imports `configureawait.props`, and `Directory.Build.props` injects package version pins MSBuild-wide. This page lists every knob, quotes the raw files, and points to representative csproj snippets that use them.

## `<Version>7.4.0</Version>`

The single source of truth for the ABP version is `common.props`:

```xml common.props
<Project>
  <PropertyGroup>
    <LangVersion>latest</LangVersion>
    <Version>7.4.0</Version>
    <NoWarn>$(NoWarn);CS1591;CS0436</NoWarn>
    <PackageIconUrl>https://abp.io/assets/abp_nupkg.png</PackageIconUrl>
    <PackageProjectUrl>https://abp.io/</PackageProjectUrl>
    <PackageLicenseExpression>LGPL-3.0-only</PackageLicenseExpression>
    <RepositoryType>git</RepositoryType>
    <RepositoryUrl>https://github.com/abpframework/abp/</RepositoryUrl>
    <PackageReadmeFile>NuGet.md</PackageReadmeFile>
    <PackageTags>aspnetcore boilerplate framework web best-practices angular maui blazor mvc csharp webapp</PackageTags>
    <GenerateDocumentationFile>true</GenerateDocumentationFile>
    <!-- Include symbol files (*.pdb) in the built .nupkg -->
    <AllowedOutputExtensionsInPackageBuildOutputFolder>$(AllowedOutputExtensionsInPackageBuildOutputFolder);.pdb</AllowedOutputExtensionsInPackageBuildOutputFolder>
  </PropertyGroup>
  <ItemGroup>
    <None Include="..\..\NuGet.md" Pack="true" PackagePath="\"/>
  </ItemGroup>
  <ItemGroup>
    <PackageReference Include="Microsoft.SourceLink.GitHub" Version="1.1.1">
      <PrivateAssets>all</PrivateAssets>
      <IncludeAssets>runtime; build; native; contentfiles; analyzers</IncludeAssets>
    </PackageReference>
  </ItemGroup>
  <ItemGroup Condition="'$(UsingMicrosoftNETSdkWeb)' != 'true' AND '$(UsingMicrosoftNETSdkRazor)' != 'true'">
    <None Remove="*.abppkg.analyze.json" />
    <Content Include="*.abppkg.analyze.json">
		<Pack>true</Pack>
		<PackagePath>content\</PackagePath>
	</Content>
    <None Remove="*.abppkg.json" />
    <Content Include="*.abppkg.json">
		<Pack>true</Pack>
		<PackagePath>content\</PackagePath>
    </Content>
  </ItemGroup>
  <ItemGroup Condition="$(AssemblyName.EndsWith('HttpApi.Client'))">
    <EmbeddedResource Include="**\*generate-proxy.json" />
    <Content Remove="**\*generate-proxy.json" />
  </ItemGroup>
</Project>
```

Every package — `Volo.Abp.Core`, `Volo.Abp.Identity.Domain`, `Volo.Abp.Cli`, the application modules under `modules/`, and the templates' transitive references — therefore ships with `Version=7.4.0`. Importing happens at the top of every csproj:

```xml framework/src/Volo.Abp.Core/Volo.Abp.Core.csproj
<Project Sdk="Microsoft.NET.Sdk">

  <Import Project="..\..\..\configureawait.props" />
  <Import Project="..\..\..\common.props" />

  <PropertyGroup>
    <TargetFrameworks>netstandard2.0;netstandard2.1;net7.0</TargetFrameworks>
    <Nullable>enable</Nullable>
    <WarningsAsErrors>Nullable</WarningsAsErrors>
    <AssemblyName>Volo.Abp.Core</AssemblyName>
    <PackageId>Volo.Abp.Core</PackageId>
    /* ... */
  </PropertyGroup>
```

## Target frameworks

There are three target-framework profiles in the repository.

| Profile | `<TargetFrameworks>` / `<TargetFramework>` | Used by | Example csproj |
| --- | --- | --- | --- |
| Multi-target portable | `netstandard2.0;netstandard2.1;net7.0` | All Domain.Shared, Application.Contracts, HttpApi.Client tiers; framework primitives that must run inside Blazor WebAssembly. | `framework/src/Volo.Abp.Core/Volo.Abp.Core.csproj` |
| `net7.0` only | `net7.0` | Domain, Application, EntityFrameworkCore, MongoDB, HttpApi tiers; anything depending on EF Core 7 or `Microsoft.AspNetCore.*` 7. | `framework/src/Volo.Abp.AspNetCore/Volo.Abp.AspNetCore.csproj` |
| `net7.0` Web SDK | `net7.0` with `Microsoft.NET.Sdk.Web` | Host projects and the AspNetCore middleware packages that need the Web SDK. | `framework/src/Volo.Abp.AspNetCore/Volo.Abp.AspNetCore.csproj` |

`Volo.Abp.Core` (the kernel) and `Volo.Abp.Ddd.Domain` (DDD) sit on the portable profile so both Blazor WebAssembly and .NET 7 hosts can consume them:

```xml framework/src/Volo.Abp.Ddd.Domain/Volo.Abp.Ddd.Domain.csproj
<Project Sdk="Microsoft.NET.Sdk">

  <Import Project="..\..\..\configureawait.props" />
  <Import Project="..\..\..\common.props" />

  <PropertyGroup>
    <TargetFrameworks>netstandard2.0;netstandard2.1;net7.0</TargetFrameworks>
    <Nullable>enable</Nullable>
    <WarningsAsErrors>Nullable</WarningsAsErrors>
    <AssemblyName>Volo.Abp.Ddd.Domain</AssemblyName>
    <PackageId>Volo.Abp.Ddd.Domain</PackageId>
    /* ... */
  </PropertyGroup>

  <ItemGroup>
    <ProjectReference Include="..\Volo.Abp.Ddd.Domain.Shared\Volo.Abp.Ddd.Domain.Shared.csproj" />
    /* ... */
  </ItemGroup>
</Project>
```

`Volo.Abp.AspNetCore` is the canonical Web-SDK package — it targets `net7.0` only because ASP.NET Core 7 doesn't ship for .NET Standard:

```xml framework/src/Volo.Abp.AspNetCore/Volo.Abp.AspNetCore.csproj
<Project Sdk="Microsoft.NET.Sdk.Web">

  <Import Project="..\..\..\configureawait.props" />
  <Import Project="..\..\..\common.props" />

  <PropertyGroup>
    <TargetFramework>net7.0</TargetFramework>
    <Nullable>enable</Nullable>
    <WarningsAsErrors>Nullable</WarningsAsErrors>
    <AssemblyName>Volo.Abp.AspNetCore</AssemblyName>
    <PackageId>Volo.Abp.AspNetCore</PackageId>
    <IsPackable>true</IsPackable>
    <OutputType>Library</OutputType>
    <NoDefaultLaunchSettingsFile>true</NoDefaultLaunchSettingsFile>
    /* ... */
  </PropertyGroup>

  <ItemGroup>
    /* ProjectReferences to Auditing, Authorization, ExceptionHandling, Http, Security, Uow, Validation, VirtualFileSystem */
    <PackageReference Include="Microsoft.AspNetCore.Authentication.OpenIdConnect" Version="$(MicrosoftAspNetCorePackageVersion)" />
    <PackageReference Include="IdentityModel" Version="6.0.0" />
  </ItemGroup>
</Project>
```

The CLI is also `net7.0` only because it ships as a global tool (`<PackAsTool>true</PackAsTool>`, `<ToolCommandName>abp</ToolCommandName>`):

```xml framework/src/Volo.Abp.Cli/Volo.Abp.Cli.csproj
<Project Sdk="Microsoft.NET.Sdk">
  <Import Project="..\..\..\configureawait.props" />
  <Import Project="..\..\..\common.props" />

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <Nullable>enable</Nullable>
    <WarningsAsErrors>Nullable</WarningsAsErrors>
    <TargetFramework>net7.0</TargetFramework>
    <PackAsTool>true</PackAsTool>
    <ToolCommandName>abp</ToolCommandName>
    <RootNamespace />
    <UserSecretsId>43599b00-4fa5-4b9f-a314-0757889b296b</UserSecretsId>
  </PropertyGroup>
```

<Note>
`netstandard2.0;netstandard2.1` are kept for backwards compatibility with downstream consumers that have not upgraded to .NET 7. The `AssetTargetFallback` line in many csproj (`portable-net45+win8+wp8+wpa81`) keeps even older PCL references resolvable.
</Note>

## `global.json` — SDK pin

The repo pins the .NET SDK to `7.0.100` with `latestFeature` roll-forward, so a developer with 7.0.x SDK above 7.0.100 in the same feature band can still build:

```json global.json
{
  "sdk": {
    "version": "7.0.100",
    "rollForward": "latestFeature"
  }
}
```

`latestFeature` rolls forward across patch versions but not minor — so 7.0.999 is fine, 7.1.x is not.

## `Directory.Build.props` — version pins

`Directory.Build.props` is automatically imported by every csproj in the repo (recursively) and provides MSBuild variables for transitive package versions. It also enables `coverlet.collector` in test projects via the `IsTestProject` flag:

```xml Directory.Build.props
<Project>
  <PropertyGroup>

    <!-- All Microsoft AspNetCore packages -->
    <MicrosoftAspNetCorePackageVersion>7.0.10</MicrosoftAspNetCorePackageVersion>

    <!-- All Microsoft EntityFrameworkCore packages -->
    <MicrosoftEntityFrameworkCorePackageVersion>7.0.10</MicrosoftEntityFrameworkCorePackageVersion>

    <!-- All Microsoft packages -->
    <MicrosoftPackageVersion>7.0.0</MicrosoftPackageVersion>

    <MicrosoftNETTestSdkPackageVersion>17.2.0</MicrosoftNETTestSdkPackageVersion>
    <NSubstitutePackageVersion>4.3.0</NSubstitutePackageVersion>
    <ShouldlyPackageVersion>4.1.0</ShouldlyPackageVersion>
    <xUnitPackageVersion>2.4.1</xUnitPackageVersion>
    <xUnitExtensibilityExecutionPackageVersion>2.4.1</xUnitExtensibilityExecutionPackageVersion>
    <xUnitRunnerVisualstudioPackageVersion>2.4.5</xUnitRunnerVisualstudioPackageVersion>
    <Mongo2GoPackageVersion>3.1.3</Mongo2GoPackageVersion>
    <MicrosoftCodeAnalysisPackageVersion>4.2.0</MicrosoftCodeAnalysisPackageVersion>
    <NUglifyPackageVersion>1.20.0</NUglifyPackageVersion>
    <PollyPackageVersion>7.2.3</PollyPackageVersion>

    <IsTestProject Condition="$(MSBuildProjectFullPath.Contains('test')) and ($(MSBuildProjectName.EndsWith('.Tests')) or $(MSBuildProjectName.EndsWith('.TestBase')))">true</IsTestProject>

    <!-- OpenIddict https://www.nuget.org/packages/OpenIddict.Core -->
    <OpenIddictPackageVersion>4.8.0</OpenIddictPackageVersion>

  </PropertyGroup>

  <ItemGroup>
    <PackageReference Condition="'$(IsTestProject)' == 'true'" Include="coverlet.collector" Version="3.1.2">
        <PrivateAssets>all</PrivateAssets>
        <IncludeAssets>runtime; build; native; contentfiles; analyzers</IncludeAssets>
    </PackageReference>
  </ItemGroup>
</Project>
```

### Summary of version pins

| MSBuild variable | Value | Used for |
| --- | --- | --- |
| `MicrosoftAspNetCorePackageVersion` | `7.0.10` | All `Microsoft.AspNetCore.*` package references. |
| `MicrosoftEntityFrameworkCorePackageVersion` | `7.0.10` | All EF Core providers (`Microsoft.EntityFrameworkCore.SqlServer`, etc.). |
| `MicrosoftPackageVersion` | `7.0.0` | All `Microsoft.Extensions.*` (DI, Options, Logging, Hosting), `System.Text.Encodings.Web`, `Microsoft.Extensions.FileProviders.Embedded`. |
| `MicrosoftNETTestSdkPackageVersion` | `17.2.0` | xUnit test runner. |
| `NSubstitutePackageVersion` | `4.3.0` | Mocking in test projects. |
| `ShouldlyPackageVersion` | `4.1.0` | Assertion library. |
| `xUnitPackageVersion` | `2.4.1` | xUnit itself. |
| `xUnitExtensibilityExecutionPackageVersion` | `2.4.1` | xUnit fixtures. |
| `xUnitRunnerVisualstudioPackageVersion` | `2.4.5` | VS test runner adapter. |
| `Mongo2GoPackageVersion` | `3.1.3` | Embedded MongoDB for tests. |
| `MicrosoftCodeAnalysisPackageVersion` | `4.2.0` | Roslyn used by `Volo.Abp.Cli`. |
| `NUglifyPackageVersion` | `1.20.0` | JS/CSS minification (`Volo.Abp.Minify`). |
| `PollyPackageVersion` | `7.2.3` | Retry / circuit-breaker in HTTP clients. |
| `OpenIddictPackageVersion` | `4.8.0` | OpenIddict server / client. |

`coverlet.collector 3.1.2` is auto-added to anything matching `test/**` and `*.Tests`/`*.TestBase`.

## `common.test.props`

Tests use a separate prop file that doesn't ship the runtime metadata:

```xml common.test.props
<Project>
  <PropertyGroup>
    <LangVersion>latest</LangVersion>
    <NoWarn>$(NoWarn);CS1591;CS0436</NoWarn>
    <GenerateRuntimeConfigurationFiles>true</GenerateRuntimeConfigurationFiles>
    <GenerateAssemblyConfigurationAttribute>false</GenerateAssemblyConfigurationAttribute>
    <GenerateAssemblyCompanyAttribute>false</GenerateAssemblyCompanyAttribute>
    <GenerateAssemblyProductAttribute>false</GenerateAssemblyProductAttribute>
  </PropertyGroup>
</Project>
```

The test pins (xUnit, NSubstitute, Shouldly versions) come from `Directory.Build.props` above.

## `latest-versions.json`

ABP CLI uses `latest-versions.json` at the repo root to decide whether a project needs an upgrade. At this revision the file is intentionally short — it records the most recent stable release:

```json latest-versions.json
[
  {
    "version": "7.3.2",
    "releaseDate": "",
    "type": "stable",
    "message": ""
  }
]
```

The CLI's update-check helpers (`framework/src/Volo.Abp.Cli/`) read it and compare to the installed `Volo.Abp.Cli` version. New stable / preview entries get pushed to this file when a release is cut from `deploy/_run_all.ps1`.

## Package metadata

`common.props` propagates the same NuGet metadata to every package:

| MSBuild property | Value | Why |
| --- | --- | --- |
| `<PackageLicenseExpression>` | `LGPL-3.0-only` | SPDX identifier; replaces the old `<licenseUrl>`. |
| `<PackageProjectUrl>` | `https://abp.io/` | Linked from nuget.org. |
| `<RepositoryUrl>` | `https://github.com/abpframework/abp/` | Required by SourceLink. |
| `<RepositoryType>` | `git` | Required by SourceLink. |
| `<PackageIconUrl>` | `https://abp.io/assets/abp_nupkg.png` | Logo on nuget.org. |
| `<PackageReadmeFile>` | `NuGet.md` | Each csproj packs `..\..\NuGet.md` into the .nupkg via the included `<None>` item. |
| `<PackageTags>` | `aspnetcore boilerplate framework web best-practices angular maui blazor mvc csharp webapp` | Search keywords on nuget.org. |
| `<GenerateDocumentationFile>` | `true` | Produces the XML doc file alongside the assembly. |
| `<NoWarn>` | `$(NoWarn);CS1591;CS0436` | Suppresses "missing XML comment" + duplicate-type warnings. |
| `<AllowedOutputExtensionsInPackageBuildOutputFolder>` | `…;.pdb` | Ships symbols inside the .nupkg. |

The `*.abppkg.json` / `*.abppkg.analyze.json` content files are conditionally packed for non-Web/non-Razor SDK projects — these are ABP-CLI metadata files describing the package's role in an ABP solution. Web/Razor SDK projects skip them because they have no content folder in the package shape.

## SourceLink

ABP ships full SourceLink debugging — every package references `Microsoft.SourceLink.GitHub 1.1.1`:

```xml common.props (excerpt)
<ItemGroup>
  <PackageReference Include="Microsoft.SourceLink.GitHub" Version="1.1.1">
    <PrivateAssets>all</PrivateAssets>
    <IncludeAssets>runtime; build; native; contentfiles; analyzers</IncludeAssets>
  </PackageReference>
</ItemGroup>
```

Combined with `<RepositoryUrl>` and `<AllowedOutputExtensionsInPackageBuildOutputFolder>` (which packs `.pdb` files), Visual Studio and Rider can step into any line of `Volo.Abp.*` source from a NuGet binary.

## `configureawait.props`

`ConfigureAwait.Fody` is added to Release builds:

```xml configureawait.props
<Project>
  <ItemGroup Condition="'$(Configuration)' == 'Release'">
      <PackageReference Include="ConfigureAwait.Fody" Version="3.3.1" PrivateAssets="All" />
      <PackageReference Include="Fody" Version="6.6.1">
        <PrivateAssets>All</PrivateAssets>
        <IncludeAssets>runtime; build; native; contentfiles; analyzers</IncludeAssets>
      </PackageReference>
  </ItemGroup>
</Project>
```

Per-project Fody configuration is in each project's `FodyWeavers.xml`:

```xml framework/src/Volo.Abp.Core/FodyWeavers.xml
<Weavers xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:noNamespaceSchemaLocation="FodyWeavers.xsd">
  <ConfigureAwait ContinueOnCapturedContext="false" />
</Weavers>
```

This rewrites every `await` in the assembly with `.ConfigureAwait(false)` so library code never re-captures the calling `SynchronizationContext`. See `/overview/conventions` for the full discussion.

## `NuGet.Config`

The repo restores from `nuget.org` only:

```xml NuGet.Config
<?xml version="1.0" encoding="utf-8"?>
<configuration>
    <packageSources>
        <add key="nuget.org" value="https://api.nuget.org/v3/index.json" />
    </packageSources>
</configuration>
```

A corresponding `NuGet.Config` ships in `templates/app/`, `templates/app-nolayers/`, `templates/module/` so generated solutions start from the same single feed.

## How a third-party project consumes 7.4.0

<Steps>
  <Step title="Install matching SDK">
    Use .NET SDK 7.0.100 or any feature-level 7.0.x release. The framework targets `net7.0` for runtime-only assemblies and `netstandard2.0;netstandard2.1;net7.0` for the portable tier; Blazor WASM only sees the latter.
  </Step>
  <Step title="Pin transitive Microsoft packages">
    Mirror `Directory.Build.props`: `Microsoft.AspNetCore.* 7.0.10`, `Microsoft.EntityFrameworkCore.* 7.0.10`, `Microsoft.Extensions.* 7.0.0`. Mismatched minor versions can introduce duplicate-assembly warnings.
  </Step>
  <Step title="Use `Volo.Abp.* 7.4.0`">
    Reference any package at exactly `7.4.0`. Mixing 7.3.x and 7.4.0 within a solution is unsupported because `common.props` propagates `Version` to every package built in the repo.
  </Step>
  <Step title="Opt in to `ConfigureAwait.Fody`">
    If you want library-style behaviour, copy `configureawait.props` and `FodyWeavers.xml` into your solution and import them next to your csproj.
  </Step>
</Steps>
