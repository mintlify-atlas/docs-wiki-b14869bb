`Volo.CmsKit.Public.HttpApi` ships the read-and-engage surface used by the
public website. Every controller extends `CmsKitPublicControllerBase`,
lives in the `cms-kit-public` area
(`CmsKitPublicRemoteServiceConsts.ModuleName`) and is wrapped by the same
two feature attributes as the admin side:

- `[RequiresGlobalFeature(typeof(<Feature>))]` — host-level kill switch.
- `[RequiresFeature(CmsKitFeatures.<Toggle>Enable)]` — per-tenant
  feature toggle.

Most endpoints are **anonymous**. Comments, ratings and reactions require
a signed-in user because the service captures the current user id; the
controllers themselves do not declare `[Authorize]`.

```text Volo.CmsKit.Public.HttpApi
Volo/CmsKit/Public/
├── Blogs/BlogPostPublicController.cs   → /api/cms-kit-public/blog-posts
├── Comments/CommentPublicController.cs → /api/cms-kit-public/comments
├── GlobalResources/GlobalResourcePublicController.cs
│                                        → /api/cms-kit-public/global-resources
├── Menus/MenuItemPublicController.cs   → /api/cms-kit-public/menu-items
├── Pages/PagesPublicController.cs      → /api/cms-kit-public/pages
├── Ratings/RatingPublicController.cs   → /api/cms-kit-public/ratings
├── Reactions/ReactionPublicController.cs → /api/cms-kit-public/reactions
└── Tags/TagPublicController.cs         → /api/cms-kit-public/tags
```

## Route summary

### Blog posts

| Verb | Path | Body | Returns |
| ---- | ---- | ---- | ------- |
| GET    | `/api/cms-kit-public/blog-posts/{blogSlug}` | `BlogPostGetListInput` | `PagedResultDto<BlogPostCommonDto>` |
| GET    | `/api/cms-kit-public/blog-posts/{blogSlug}/{blogPostSlug}` | — | `BlogPostCommonDto` |
| GET    | `/api/cms-kit-public/blog-posts/authors` | `BlogPostFilteredPagedAndSortedResultRequestDto` | `PagedResultDto<CmsUserDto>` |
| GET    | `/api/cms-kit-public/blog-posts/authors/{id}` | — | `CmsUserDto` |
| DELETE | `/api/cms-kit-public/blog-posts/{id}` | — | `204` |

The `DELETE` is callable only by the post's author (the service checks
`CurrentUser.Id`); it lets a contributor recall a post they wrote without
needing the admin permission.

### Comments

## Selected controllers

### BlogPostPublicController

```csharp modules/cms-kit/src/Volo.CmsKit.Public.HttpApi/Volo/CmsKit/Public/Blogs/BlogPostPublicController.cs
[RequiresFeature(CmsKitFeatures.BlogEnable)]
[RequiresGlobalFeature(typeof(BlogsFeature))]
[RemoteService(Name = CmsKitPublicRemoteServiceConsts.RemoteServiceName)]
[Area(CmsKitPublicRemoteServiceConsts.ModuleName)]
[Route("api/cms-kit-public/blog-posts")]
public class BlogPostPublicController : CmsKitPublicControllerBase, IBlogPostPublicAppService
{
    [HttpGet] [Route("{blogSlug}/{blogPostSlug}")]
    public virtual Task<BlogPostCommonDto> GetAsync(string blogSlug, string blogPostSlug)
        => BlogPostPublicAppService.GetAsync(blogSlug, blogPostSlug);

    [HttpGet] [Route("{blogSlug}")]
    public virtual Task<PagedResultDto<BlogPostCommonDto>> GetListAsync(string blogSlug, BlogPostGetListInput input)
        => BlogPostPublicAppService.GetListAsync(blogSlug, input);

    [HttpGet] [Route("authors")]
    public virtual Task<PagedResultDto<CmsUserDto>> GetAuthorsHasBlogPostsAsync(BlogPostFilteredPagedAndSortedResultRequestDto input)
        => BlogPostPublicAppService.GetAuthorsHasBlogPostsAsync(input);

    [HttpGet] [Route("authors/{id}")]
    public virtual Task<CmsUserDto> GetAuthorHasBlogPostAsync(Guid id)
        => BlogPostPublicAppService.GetAuthorHasBlogPostAsync(id);

    [HttpDelete] [Route("{id}")]
    public virtual Task DeleteAsync(Guid id) => BlogPostPublicAppService.DeleteAsync(id);
}
```


### CommentPublicController

```csharp modules/cms-kit/src/Volo.CmsKit.Public.HttpApi/Volo/CmsKit/Public/Comments/CommentPublicController.cs
[RequiresFeature(CmsKitFeatures.CommentEnable)]
[RequiresGlobalFeature(typeof(CommentsFeature))]
[Route("api/cms-kit-public/comments")]
public class CommentPublicController : CmsKitPublicControllerBase, ICommentPublicAppService
{
    [HttpGet] [Route("{entityType}/{entityId}")]
    public Task<ListResultDto<CommentWithDetailsDto>> GetListAsync(string entityType, string entityId)
        => CommentPublicAppService.GetListAsync(entityType, entityId);

    [HttpPost] [Route("{entityType}/{entityId}")]
    public Task<CommentDto> CreateAsync(string entityType, string entityId, CreateCommentInput input)
        => CommentPublicAppService.CreateAsync(entityType, entityId, input);

    [HttpPut] [Route("{id}")]
    public Task<CommentDto> UpdateAsync(Guid id, UpdateCommentInput input)
        => CommentPublicAppService.UpdateAsync(id, input);

    [HttpDelete] [Route("{id}")]
    public Task DeleteAsync(Guid id) => CommentPublicAppService.DeleteAsync(id);
}
```

`UpdateAsync`/`DeleteAsync` check that `CurrentUser.Id` matches the
comment's `CreatorId`; otherwise the service throws
`AbpAuthorizationException`.

```http
POST /api/cms-kit-public/comments/Volo.CmsKit.Blogs.BlogPost/3fa85f64-... HTTP/1.1
Content-Type: application/json
Authorization: Bearer <user-token>

{
  "text": "Great post!",
  "repliedCommentId": null
}
```

```json
{
  "id": "ce003e44-...",
  "text": "Great post!",
  "repliedCommentId": null,
  "entityType": "Volo.CmsKit.Blogs.BlogPost",
  "entityId": "3fa85f64-...",
  "creatorId": "bd0c2b00-...",
  "creationTime": "2025-01-15T11:00:00Z"
}
```

The hierarchical reply tree comes back via `GET` of the same path — top
level comments and their `Replies` collection.

### RatingPublicController

```csharp modules/cms-kit/src/Volo.CmsKit.Public.HttpApi/Volo/CmsKit/Public/Ratings/RatingPublicController.cs
[Route("api/cms-kit-public/ratings")]
public class RatingPublicController : CmsKitPublicControllerBase, IRatingPublicAppService
{
    [HttpPut] [Route("{entityType}/{entityId}")]
    public virtual Task<RatingDto> CreateAsync(string entityType, string entityId, CreateUpdateRatingInput input)
        => RatingPublicAppService.CreateAsync(entityType, entityId, input);

    [HttpDelete] [Route("{entityType}/{entityId}")]
    public virtual Task DeleteAsync(string entityType, string entityId)
        => RatingPublicAppService.DeleteAsync(entityType, entityId);

    [HttpGet] [Route("{entityType}/{entityId}")]
    public virtual Task<List<RatingWithStarCountDto>> GetGroupedStarCountsAsync(string entityType, string entityId)
        => RatingPublicAppService.GetGroupedStarCountsAsync(entityType, entityId);
}
```

`CreateAsync` is a `PUT` because a user has at most one rating per entity
— the call is upsert semantics. `CreateUpdateRatingInput` carries a
single field `StarCount` between 1 and 5.

```http
PUT /api/cms-kit-public/ratings/Volo.CmsKit.Blogs.BlogPost/3fa85f64-... HTTP/1.1
Content-Type: application/json
Authorization: Bearer <user-token>

{ "starCount": 5 }
```

```json
{
  "id": "1c1e4f10-...",

  "entityType": "Volo.CmsKit.Blogs.BlogPost",
  "entityId": "3fa85f64-...",
```


### ReactionPublicController

```csharp modules/cms-kit/src/Volo.CmsKit.Public.HttpApi/Volo/CmsKit/Public/Reactions/ReactionPublicController.cs
[Route("api/cms-kit-public/reactions")]
public class ReactionPublicController : CmsKitPublicControllerBase, IReactionPublicAppService
{
    [HttpGet] [Route("{entityType}/{entityId}")]
    public virtual Task<ListResultDto<ReactionWithSelectionDto>> GetForSelectionAsync(string entityType, string entityId)
        => ReactionPublicAppService.GetForSelectionAsync(entityType, entityId);

    [HttpPut] [Route("{entityType}/{entityId}/{reaction}")]
    public virtual Task CreateAsync(string entityType, string entityId, string reaction)
        => ReactionPublicAppService.CreateAsync(entityType, entityId, reaction);

    public virtual Task DeleteAsync(string entityType, string entityId, string reaction)
        => ReactionPublicAppService.DeleteAsync(entityType, entityId, reaction);
```

`reaction` is one of the names registered via the
`CmsKitReactionOptions` — out of the box: `thumbs-up`, `confused`,
`eyes`, `heart`, `hooray`, `laugh`, `rocket`, `smile`.

```http
PUT /api/cms-kit-public/reactions/Volo.CmsKit.Blogs.BlogPost/3fa85f64-.../heart HTTP/1.1
Authorization: Bearer <user-token>
```

## Multi-tenancy

Public CMS Kit reads are tenant-aware just like the admin side. The
public site typically resolves the tenant from the host (subdomain or
custom domain) via `Volo.Abp.AspNetCore.MultiTenancy`'s
`DomainTenantResolver`. When you call the endpoints from a separate
front-end, pass the `__tenant` header to keep the response inside the
right tenant scope:

```http
GET /api/cms-kit-public/pages/about HTTP/1.1
__tenant: contoso
```

## Common error envelope

A bad slug returns the standard 404 envelope:

```json
{
  "error": {
    "code": "Volo.Abp.Domain:Entities.EntityNotFound",
    "message": "There is no entity Page with slug 'about-us'.",
    "details": null
  }
}
```
