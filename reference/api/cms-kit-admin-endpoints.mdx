`Volo.CmsKit.Admin.HttpApi` ships the admin write surface. Every controller
extends `CmsKitAdminController`, lives in the `cms-kit-admin` area
(`CmsKitAdminRemoteServiceConsts.ModuleName`), and is gated by two ABP
attributes:

- `[RequiresGlobalFeature(typeof(<Feature>))]` — host can disable the
  whole sub-module at startup.
- `[RequiresFeature(CmsKitFeatures.<Toggle>Enable)]` — tenant can turn
  it off at runtime through the feature-management UI.

The class-level `[Authorize(CmsKitAdminPermissions.<Group>.Default)]`
demands the read policy; create/update/delete/special actions add their
own `[Authorize]` overrides.

```text Volo.CmsKit.Admin.HttpApi
Volo/CmsKit/Admin/
├── Blogs/
│   ├── BlogAdminController.cs        → /api/cms-kit-admin/blogs
│   ├── BlogPostAdminController.cs    → /api/cms-kit-admin/blogs/blog-posts
│   └── BlogFeatureAdminController.cs → /api/cms-kit-admin/blogs/{blogId}/features
├── Comments/CommentAdminController.cs    → /api/cms-kit-admin/comments
├── Pages/PageAdminController.cs          → /api/cms-kit-admin/pages
├── Tags/
│   ├── TagAdminController.cs         → /api/cms-kit-admin/tags
│   └── EntityTagAdminController.cs   → /api/cms-kit-admin/entity-tags
├── Menus/MenuItemAdminController.cs      → /api/cms-kit-admin/menu-items
├── GlobalResources/GlobalResourceAdminController.cs
│                                      → /api/cms-kit-admin/global-resources
└── MediaDescriptors/MediaDescriptorAdminController.cs
                                       → /api/cms-kit-admin/media
```

## Selected controllers

### BlogAdminController

```csharp modules/cms-kit/src/Volo.CmsKit.Admin.HttpApi/Volo/CmsKit/Admin/Blogs/BlogAdminController.cs
[RequiresFeature(CmsKitFeatures.BlogEnable)]
[RequiresGlobalFeature(typeof(BlogsFeature))]
[RemoteService(Name = CmsKitAdminRemoteServiceConsts.RemoteServiceName)]
[Area(CmsKitAdminRemoteServiceConsts.ModuleName)]
[Authorize(CmsKitAdminPermissions.Blogs.Default)]
[Route("api/cms-kit-admin/blogs")]
public class BlogAdminController : CmsKitAdminController, IBlogAdminAppService
{
    [HttpGet] [Route("{id}")]
    public Task<BlogDto> GetAsync(Guid id) => BlogAdminAppService.GetAsync(id);

    [HttpGet]
    public Task<PagedResultDto<BlogDto>> GetListAsync(BlogGetListInput input)
        => BlogAdminAppService.GetListAsync(input);

    [HttpPost]
    [Authorize(CmsKitAdminPermissions.Blogs.Create)]
    public Task<BlogDto> CreateAsync(CreateBlogDto input) => BlogAdminAppService.CreateAsync(input);

    [HttpPut] [Route("{id}")]
    [Authorize(CmsKitAdminPermissions.Blogs.Update)]
    public Task<BlogDto> UpdateAsync(Guid id, UpdateBlogDto input)
        => BlogAdminAppService.UpdateAsync(id, input);

    [HttpDelete] [Route("{id}")]
    [Authorize(CmsKitAdminPermissions.Blogs.Delete)]
    public Task DeleteAsync(Guid id) => BlogAdminAppService.DeleteAsync(id);
}
```

Example create:

```http
POST /api/cms-kit-admin/blogs HTTP/1.1
Content-Type: application/json
Authorization: Bearer ...

{
  "name": "Company blog",
  "slug": "company-blog",
  "description": null
}
```

```json
{
  "id": "3fa85f64-...",
  "name": "Company blog",
  "slug": "company-blog",
  "description": null,
  "creationTime": "2025-01-15T10:00:00Z"
}
```

### BlogPostAdminController

The post controller is the busiest in CMS Kit — it carries the full CRUD
plus the publishing workflow (`publish`, `draft`, `send-to-review`).

```csharp modules/cms-kit/src/Volo.CmsKit.Admin.HttpApi/Volo/CmsKit/Admin/Blogs/BlogPostAdminController.cs
[Route("api/cms-kit-admin/blogs/blog-posts")]
public class BlogPostAdminController : CmsKitAdminController, IBlogPostAdminAppService
{
    [HttpPost]
    [Authorize(CmsKitAdminPermissions.BlogPosts.Create)]
    public virtual Task<BlogPostDto> CreateAsync(CreateBlogPostDto input)
        => BlogPostAdminAppService.CreateAsync(input);

    [HttpPost]
    [Route("{id}/publish")]
    [Authorize(CmsKitAdminPermissions.BlogPosts.Publish)]
    public virtual Task PublishAsync(Guid id) => BlogPostAdminAppService.PublishAsync(id);

    [HttpPost]
    [Route("create-and-publish")]
    [Authorize(CmsKitAdminPermissions.BlogPosts.Create)]
    [Authorize(CmsKitAdminPermissions.BlogPosts.Publish)]
    public virtual Task<BlogPostDto> CreateAndPublishAsync(CreateBlogPostDto input)
        => BlogPostAdminAppService.CreateAndPublishAsync(input);

    [HttpGet] [Route("has-blogpost-waiting-for-review")]
    [Authorize(CmsKitAdminPermissions.BlogPosts.Publish)]
    public virtual Task<bool> HasBlogPostWaitingForReviewAsync()
        => BlogPostAdminAppService.HasBlogPostWaitingForReviewAsync();

    // …GetAsync, GetListAsync, UpdateAsync, DeleteAsync, DraftAsync, SendToReviewAsync omitted…
}
```

`PublishAsync` flips the `Status` field on the post entity to `Published`
and sets `PublishTime` — only callers with `CmsKit.BlogPosts.Publish` may
do that.

```http
POST /api/cms-kit-admin/blogs/blog-posts HTTP/1.1
Content-Type: application/json

{
  "blogId": "3fa85f64-...",
  "title": "Welcome to our blog",
  "slug": "welcome",
  "shortDescription": "First post.",
  "content": "<p>Hello!</p>",
  "coverImageMediaId": "8c7b4f10-...",
  "tagNames": ["news", "intro"]
}
```

The same body sent to `/create-and-publish` short-circuits the
review/draft state machine.

### PageAdminController

```csharp modules/cms-kit/src/Volo.CmsKit.Admin.HttpApi/Volo/CmsKit/Admin/Pages/PageAdminController.cs
[Route("api/cms-kit-admin/pages")]
public class PageAdminController : CmsKitAdminController, IPageAdminAppService

        => PageAdminAppService.CreateAsync(input);

    [Authorize(CmsKitAdminPermissions.Pages.Update)]

    [Authorize(CmsKitAdminPermissions.Pages.Delete)]
```

`SetAsHomePageAsync` flips a singleton flag — only one page per tenant

### TagAdminController / EntityTagAdminController

`TagAdminController` exposes a full CRUD for tag entities, plus a
read-only endpoint for **tag definitions** — the static list of tag
groups registered through `CmsKitTagOptions`.

```csharp modules/cms-kit/src/Volo.CmsKit.Admin.HttpApi/Volo/CmsKit/Admin/Tags/TagAdminController.cs (excerpt)
[HttpGet] [Route("tag-definitions")]
public Task<List<TagDefinitionDto>> GetTagDefinitionsAsync()
    => TagAdminAppService.GetTagDefinitionsAsync();
```

`EntityTagAdminController` lets the admin attach/detach a tag from an
arbitrary entity — useful for tagging a product, a page, a post… by id:

```http
POST /api/cms-kit-admin/entity-tags HTTP/1.1
Content-Type: application/json

{
  "entityType": "Volo.CmsKit.Pages.Page",
  "entityId": "3fa85f64-...",
  "tagName": "featured"
}
```

```http
PUT /api/cms-kit-admin/entity-tags HTTP/1.1

{
  "entityType": "Volo.CmsKit.Pages.Page",
  "entityId": "3fa85f64-...",
  "tags": ["featured", "promoted"]
}
```

### MediaDescriptorAdminController

```csharp modules/cms-kit/src/Volo.CmsKit.Admin.HttpApi/Volo/CmsKit/Admin/MediaDescriptors/MediaDescriptorAdminController.cs
[RequiresGlobalFeature(typeof(MediaFeature))]
[Route("api/cms-kit-admin/media")]
public class MediaDescriptorAdminController : CmsKitAdminController, IMediaDescriptorAdminAppService

    [HttpDelete] [Route("{id}")]
    public virtual Task DeleteAsync(Guid id)
        => MediaDescriptorAdminAppService.DeleteAsync(id);

```

Uploads are `multipart/form-data` — `CreateMediaInputWithStream` carries
both metadata and the `RemoteStreamContent` file. The returned
`MediaDescriptorDto` exposes the `Id` that the
[common `MediaDescriptorController`](/reference/api/cms-kit-endpoints#mediadescriptorcontroller)
streams back over `GET /api/cms-kit/media/{id}`.

```http
POST /api/cms-kit-admin/media/Volo.CmsKit.Blogs.BlogPost HTTP/1.1
Content-Type: multipart/form-data; boundary=...

--...
Content-Disposition: form-data; name="Name"
cover.png
--...
Content-Disposition: form-data; name="File"; filename="cover.png"
Content-Type: image/png

<raw PNG bytes>
--...--
```

```json
{
  "id": "8c7b4f10-...",
  "name": "cover.png",
  "mimeType": "image/png",
  "size": 14920,
  "entityType": "Volo.CmsKit.Blogs.BlogPost"
}
```

## Multi-tenancy

CMS Kit data is tenant-scoped — a blog, page or menu created with
`__tenant: contoso` is visible only inside `contoso`. A host caller
without `__tenant` operates on the host's CMS content (rare; in most
deployments CMS content lives inside a tenant). Pass the header on every
admin request to point at the right tenant:

```http
POST /api/cms-kit-admin/blogs HTTP/1.1
__tenant: contoso
Authorization: Bearer <admin-token>
Content-Type: application/json

{ "name": "Company blog", "slug": "company-blog" }
```
